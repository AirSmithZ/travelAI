## 1. 目标与参考标准

### 1.1 产品目标

总览路线图是一张**可扫读、可编辑、可导出**的行程信息图。用户应在一张图内同时获得：

| 层级 | 用户问题 | 必须回答 |
|------|----------|----------|
| 行程 | 一共几天？ | 列数 = `days.length` |
| 日期 | 哪天是哪天？ | 月日、星期、Day 序号 |
| 天气 | 那天穿什么？ | 温度区间、天气图标、中文描述 |
| 区域 | 今天在哪个区活动？ | 左侧区域轨 + 单元格落位 |
| 顺序 | 先去哪再去哪？ | 节点序号 + 连线方向 |
| 节点 | 这个点是什么？ | 名称、类型、时间、描述、开销等 |
| 通勤 | 怎么过去、多久？ | 交通方式图标 + 耗时 |
| 备选 | 有没有可选项？ | 虚线节点 + 备选路线分支 |

### 1.2 参考图 `map.png` 要素拆解

参考图为**深色底 + 高信息密度信息图**，核心视觉语言如下：

```
┌─────────┬── 10/16 四 · 32~34° ☀☁ ──┬── 10/18 六 · ... ──┐
│  图例   │  [色块节点]─🚶5m─[色块]─🚇20m─[色块]  │  ...              │
│  酒店   ├──────────────────────────────────────┤                   │
│  餐厅   │ 樟宜区（浅蓝行底）  T1/T2虚线框组      │                   │
│  小吃   ├──────────────────────────────────────┤                   │
│  可选   │ 武吉士区（浅黄行底）  ...              │                   │
│  游玩   ├──────────────────────────────────────┤                   │
│  航班   │ 万礼区（浅绿行底）  ⓘ 接驳说明文字块   │                   │
└─────────┴────────────────────────────────────────┴───────────────────┘
```

| 要素 | map.png 表现 | 设计意图 |
|------|-------------|----------|
| 列头 | `10月16号 四` + `32~34°` + 晴/云图标 | 日期与天气一眼可见 |
| 区域行 | 竖排区域名 + **行级浅色底**（蓝/黄/绿） | 地理分区感，非棋盘格 |
| 节点 | **类别色块**（非细边框）+ 图标 + 名称 + 楼层 | 类型可扫读 |
| 时间 | 节点旁/上下 `08:30→11:30` 或 `15:00` | 节奏感 |
| 连线 | 水平箭头线 + 交通图标 + `5min`/`1h` | 通勤信息在线上 |
| 备选 | 虚线边框节点 + 虚线分支 | 与主路线区分 |
| 分组 | T1/T2 虚线外框（场景组） | 同场景聚合 |
| 提示 | ⓘ 圆圈 + 短说明；大块文字（接驳票价） | 关键须知不丢 |
| 图例 | 第一列嵌入类别色说明 | 降低认知成本 |

**与旧分析文档的分歧（重要）**

旧文档 Phase 1 建议总览卡片「只保留序号 + 名称 + 时间」，把 tags/tips 藏进侧栏。这与 `map.png` 及本次需求（名称、描述、开销、游玩时间、类型等）**方向相反**。

**修正原则**：总览 ≠ 极简索引。总览 = **信息图密度**，通过**结构化排版 + 类别色系统 + 连线层**消化信息量，而非删掉字段。

## 2. 信息清单与数据映射

### 2.1 列头（Day Column Header）

| 展示字段 | 数据来源 | 格式建议 | 现状 |
|----------|----------|----------|------|
| Day 序号 | `day.day_index` | `Day 1` | ✅ |
| 日期 | `day.date` | `10月16日` 或 `10/16` | ⚠️ 仅 `MM-DD` |
| 星期 | `day.weekday` | `周四` | ✅ |
| 温度区间 | `day.weather.temp_min/max` | `26~34°` | ✅ |
| 天气图标 | `day.weather.icon` | 晴/多云/雨 SVG | ⚠️ 仅 ☀/☁ 二值 |
| 天气描述 | `day.weather.description` | `晴转多云` | ❌ 未展示 |
| 当日主题 | `day.label` | `第1天·抵达樟宜` | ❌ 未展示 |

### 2.2 区域轨（Region Rail）

| 展示字段 | 数据来源 | 格式建议 | 现状 |
|----------|----------|----------|------|
| 区域名 | `node.region` → `day.region` → `其他` | 中文，如「樟宜区」 | ✅ |
| 行底色 | 区域索引或区域色 token | 低饱和 tint（参考 map 蓝/黄/绿） | ⚠️ 仅交替灰底 |
| 区域图标 | 可选扩展 | 地图 pin / 区域简写 | ❌ |

**当日主区域**：若一天跨多区，左侧轨展示**全部涉及区域**（每区一行）；列头可补充 `day.region` 作为「今日主轴」摘要（可选）。

### 2.3 节点卡（Node Card）

| 展示字段 | 数据来源 | 展示策略 | 现状 |
|----------|----------|----------|------|
| 名称 | `node.name` | 主标题，1~2 行 | ✅ |
| 节点类型 | `node.category` | 色块底 + 图标 + 中文 label | ⚠️ 仅 6px 色点 |
| 游玩时间 | `start_time`–`end_time` 或 `duration_minutes` | `09:00–10:30` 或 `约 90 分钟` | ⚠️ 仅时间段 |
| 楼层/位置 | `node.floor` | `L1` / `3F` 角标 | ❌ |
| 描述/提示 | `node.tips[]` | 单行摘要或 ⓘ 悬停 | ❌ |
| 标签 | `node.tags[]` | 最多 1~2 个 chip | ❌ |
| 开销 | **无字段** | 见 §2.5 | ❌ |
| 是否备选 | `node.is_optional` | 虚线边框 +「可选」角标 | ⚠️ 仅虚线 |
| 全局序号 | 当日 primary 拓扑序 | `①` 或 `1` | ✅ |
| 场景分组 | `node.scene_group` | 虚线外框包裹同组 | ❌ 仅单日模式有 |
| 坐标置信 | `coord_confidence` | 黄点/灰点（medium 以下） | ❌ |

### 2.4 连线（Edge / Commute）

| 展示字段 | 数据来源 | 展示策略 | 现状 |
|----------|----------|----------|------|
| 交通方式 | `edge.transport_mode` | 图标（🚶🚇🚌🚕✈） | ❌ 列内无连线 UI |
| 通勤时间 | `edge.duration_minutes` | `5min` / `50min` / `1h` | ❌ |
| 路线类型 | `edge.type` | primary 实线 / alternative 虚线 | ❌ |
| 中文标注 | `edge.label` | 优先于拼接 | ❌ |
| 出发到达 | `depart_time` / `arrive_time` | 可选，航班/长途 | ❌ |
| 距离 | `distance_meters` | 步行可显示 `800m` | ❌ |

**连线范围（三类）**

```
① 同单元格内（同天同区）   A ──5m── B ──20m── C     水平链，map.png 主体
② 同天跨区               A（樟宜区）╲
                              ╲ 🚇30m
                               B（市区）
③ 跨天                   顶部通道或列边界竖井（已有 cross_day_edges 雏形）
```

现状：`OverviewEdgeLayer` **仅绘制 cross_day_edges**；列内用 4px 竖线 `overview-cell__connector`，无交通信息；**同天跨区边完全不画**。

### 2.5 数据契约扩展（已定案）

#### 开销 `cost` / `cost_label`（Q1 ✅ 扩 schema）

`ItineraryNode` 新增可选字段，**前后端同步**（见 §7.2）：

```typescript
type CostPer = 'person' | 'total' | 'group';

interface NodeCost {
  amount?: number;       // 金额，如 2.5、80
  currency?: string;     // ISO 4217：CNY | SGD | USD …
  per?: CostPer;         // person=按人 total=总计 group=按团
  note?: string;         // 「含门票」「不含餐饮」
}

interface ItineraryNode {
  // ...现有字段
  /** 展示用文案，优先于 cost 格式化，如「约 80 元/人」「免费」 */
  cost_label?: string;
  /** 结构化金额，便于当日汇总与导出统计 */
  cost?: NodeCost;
}
```

**展示优先级**：`cost_label` > 由 `cost` 格式化 > 不占位。

**格式化规则**（前端 `formatNodeCost()` 统一实现）：

| cost | 输出示例 |
|------|----------|
| `{ amount: 2.5, currency: 'SGD', per: 'person' }` | `2.5 新币/人` |
| `{ amount: 0, ... }` 或 label 含「免费」 | `免费` |
| 仅有 `note` | 显示 note |

#### 描述（Q5 ✅ `tips[0]`）

总览节点卡展示 `tips[0]` 作单行摘要；`tips[1..]` 仅在 hover / 侧栏 / ⓘ 展开。**不新增 `description` 字段**。

#### 天气（Q7 ✅ 手动编辑 + 预留 LLM tool）

`DayPlan.weather` 保持现有结构，扩展 `icon` 枚举与 `source` 溯源字段（见 §7.3）。

### 2.6 其他可补充信息

| 信息 | 来源 | 展示位置 |
|------|------|----------|
| 行程标题 | `itinerary.title` | 导出海报顶栏 / 角标区 |
| 目的地 | `itinerary.destination` | 角标区 |
| 当日节点数 | 统计 | 列头次要文字 `6 站` |
| 当日总通勤 | 累加 `edges.duration_minutes` | 列头或底部摘要 |
| 当日预估花费 | 累加 `cost`（若有） | 列头或底部 |
| LLM 警告 | `meta.warnings[]` | 总览顶部横幅 |
| 图例 | `CATEGORY_META` | 左上角（map.png 第一列） |

## 3. 现状与差距总览

### 3.1 架构现状

```
OverviewGraphView
├── 列头（日期/天气部分字段）
├── RegionRail（区域名）
├── overview-cell（区域×日期矩阵）
│   └── overview-cell__route（纵向叠放节点）  ← 与 map.png 水平链不符
│       ├── OverviewNodeCard（极简胶囊）
│       └── overview-cell__connector（4px 竖线，无交通信息）
└── OverviewEdgeLayer（仅 cross_day_edges）
```

### 3.2 差距矩阵

| 能力 | map.png | 设计文档 §3.3.1 | 当前代码 | 优先级 |
|------|---------|----------------|----------|--------|
| 区域×日期矩阵 | ✅ | ✅ | ✅ | — |
| 列内水平路线链 | ✅ | ✅ dagre LR | ❌ 纵向叠放 | **P0** |
| 列内通勤连线+图标 | ✅ | ✅ | ❌ | **P0** |
| 类别色块节点 | ✅ | 部分 | ❌ 色点 | **P0** |
| 场景分组虚线框 | ✅ | ✅ | ❌ | **P1** |
| 备选边分支 | ✅ | ✅ | ❌ | **P1** |
| 同天跨区连线 | ✅ | 未明确 | ❌ | **P1** |
| 节点描述/提示 | ✅ | 建议隐藏 | ❌ | **P1** |
| 节点开销 | ✅ | 未提及 | ❌ 无字段 | **P1** |
| 图例 | ✅ | 未提及 | ❌ 简陋 | **P2** |
| 区域行 tint 色 | ✅ | 交替灰底 | ⚠️ 弱 | **P2** |
| 天气完整展示 | ✅ | ✅ | ⚠️ 部分 | **P2** |
| 跨日通道 | ✅ | ✅ | ✅ 基础 | P2 抛光 |

### 3.3 根因（功能向）

1. **布局方向错误**：列内 `flex-direction: column` 导致无法在同一区域展示水平路线链，也无法在节点之间插入通勤标签。
2. **连线层 scope 过窄**：`OverviewEdgeLayer` 只服务 `cross_day_edges`，日内 `days[].edges` 未参与总览渲染。
3. **节点组件降级过度**：`OverviewNodeCard` 相对单日 `TripNode` 删减了 icon、category、floor、tags、tips，未向 map.png 的色块信息图靠拢。
4. **场景分组未移植**：`sceneGroups.ts` + `SceneGroupNode` 仅在 `ItineraryGraph` 使用。
5. **数据层缺开销**：无法展示 map.png 中的票价/人均信息。

## 4. 推荐实现方案

### 4.1 总体策略：矩阵信息图（方案 A+）

保留 **区域行 × 日期列** 矩阵（与产品文档、`map.png` 一致），一次性补齐：

- 列内 **水平 LR 路线链**（对齐设计文档 §3.3.1 原意）
- **三层连线**（单元格内 / 跨区 / 跨日）
- **map.png 式节点色块**（类别色作背景 tint，非整卡渐变）
- **分层信息**：默认展示核心字段；描述/长 tips 用 ⓘ 或 hover 展开

不采用旧文档「总览只留 3 字段」的极简策略。

### 4.2 组件架构（目标态）

```
OverviewGraphView
├── OverviewLegend              # 类别图例（sticky 左上角）
├── OverviewColumnHeader        # 日期/天气/主题
├── OverviewRegionRail          # 区域名 + 行色条
├── OverviewMatrix
│   ├── OverviewCell            # (dayIndex, region)
│   │   ├── OverviewSceneGroup  # scene_group 虚线框
│   │   ├── OverviewRouteChain  # 水平 flex / 可横滚
│   │   │   ├── OverviewNodeCard
│   │   │   └── OverviewCommuteEdge  # 两节点间通勤（DOM 或 SVG）
│   │   └── OverviewCellNote    # 单元格级长说明（如接驳巴士）
│   └── OverviewEdgeLayer       # 跨区 + 跨日 SVG（正交路由）
└── OverviewDaySummary          # 可选：列底当日统计
```

### 4.3 布局算法

#### 4.3.1 区域与单元格（沿用）

`layoutOverview()` 继续按 `(dayIndex, region)` 分组，`sortNodesByPrimaryEdges` 确定列内顺序。

#### 4.3.2 列内水平链（改造重点）

```typescript
// 伪代码：列内布局
const NODE_W = compact ? 120 : 148;
const COMMUTE_W = 56;  // 通勤标签区宽度
const GAP = 8;

// 按 primary 拓扑序水平排列
let x = CELL_PADDING;
for (const node of primaryChain) {
  placeNode(node, x);
  x += NODE_W + GAP;
  const edge = nextPrimaryEdge(node);
  if (edge) {
    placeCommute(edge, x);
    x += COMMUTE_W + GAP;
  }
}
// 备选边：从分支点向下或向上折出支路（见 4.4.2）
```

- 节点 > 4 个：单元格 `overflow-x: auto` + 右侧渐隐遮罩
- 行高 = `max(各列单元格内容高)`，随节点卡高度自适应
- `ResizeObserver` 回写锚点，修正 SVG 端点

#### 4.3.3 跨区连线（正交路由）

同天、不同 `region` 的 primary 边：

```
[节点 A] 樟宜区 row
    │
    │  沿列内 x 对齐走竖线到行间隙
    ▼
[节点 B] 市区 row
```

路径：`水平 → 竖直（行间隙）→ 水平`，避免贝塞尔穿卡。

### 4.4 连线渲染

#### 4.4.1 列内通勤（OverviewCommuteEdge）

优先 **DOM 组件**（与 map.png 标签一致），便于排版 emoji/文字：

```html
<div class="overview-commute">
  <span class="overview-commute__line" />
  <span class="overview-commute__badge">🚇 20min</span>
  <span class="overview-commute__arrow" />
</div>
```

- `primary`：实线 + 不透明
- `alternative`：虚线 + `opacity: 0.5`，hover 高亮
- 选中边：复用 `selectedEdgeId`

#### 4.4.2 备选路线

- **备选节点**（`is_optional`）：虚线边框 + 右上角「可选」
- **备选边**（`type: alternative`）：
  - 若目标节点在同单元格：从分支点向下折线连接（不挤占主水平链）
  - 若跨单元格：用浅色虚线 + 较低 z-index

#### 4.4.3 跨日

保留顶部 `cross_day_channel`；路径仅走通道，标签显示交通方式。

### 4.5 节点视觉规范（对齐 map.png + design-taste）

**形态**：圆角矩形色块，非细边框卡片。

```
┌──────────────────────┐
│ 📷 游玩    L2        │  ← 图标 + 类别 label + 楼层
│ 星耀樟宜 Jewel        │  ← 名称 13px/600
│ 07:15–09:00 · 约105分 │  ← 时间 + 停留
│ 约 免费        ⓘ     │  ← cost_label + tips 入口
└──────────────────────┘
  背景: color-mix(categoryColor 18%, bg-panel)
  左边线: 3px solid categoryColor
```

| Token | 值 |
|-------|-----|
| 最小尺寸 | `148×72`（紧凑 `120×60`） |
| 类别色 | `CATEGORY_META[category].color` |
| 选中 | `box-shadow: 0 0 0 2px var(--accent)` |
| 可选 | `border: 1.5px dashed` + `可选` 角标 |
| 时间 | `tabular-nums`，`--text-muted` |
| 开销 | `11px`，`--text-dim`，无数据不占位 |

**廉价感规避**（design-taste-frontend）：

- 类别色用于 **左边线 + 浅底**，禁止整卡高饱和填充
- 交通 emoji 统一 `14px` 容器，与 `TripEdge` 一致
- 区域行 tint：`color-mix(regionHue 8%, bg-base)`，不超过 3 种色相循环

### 4.6 场景分组（OverviewSceneGroup）

复用 `sceneGroups.ts`：

1. 单元格内按 `scene_group` 聚类
2. 同组 ≥ 2 节点时包一层虚线圆角框 + 左上角组名（如「T1」「樟宜机场」）
3. 组内仍走水平链

### 4.7 提示与长文本（OverviewCellNote）

满足 map.png 中「万礼接驳」类大块说明：

- 触发条件：`tips` 合并长度 > 40 字，或存在 `cell_notes`（可选日级字段）
- 展示：单元格底部浅色条，`font-size: 10px`，最多 3 行 + 展开
- 短 tips：节点卡 ⓘ 图标，`title` 或 Popover

### 4.8 图例（OverviewLegend）

嵌入左上角 corner 区（`overview-shell__corner`）：

| 色块 | 类别 |
|------|------|
| 灰 | 酒店 |
| 深红 | 餐厅 |
| 橙 | 小吃 |
| 黄 | 游玩 |
| 紫 | 地标 |
| 绿 | 机场/航班 |
| 虚线框 | 可选 |

与 `CATEGORY_META` 单一数据源。

### 4.9 交互（保持并增强）

| 交互 | 行为 |
|------|------|
| 单击节点 | 选中 + 同步 `activeDayIndex` + 侧栏编辑 |
| 双击节点 | 跳转地图 Tab 并选中 |
| 单击通勤边 | 选中边 + 侧栏 `EdgeEditor` |
| 单击列头 / DayChip | 横向滚动居中 + 列高亮 2s |
| 鸟瞰模式 | 每格最多 3 节点 + `+N`，展开后恢复全链 |
| 导出 PNG/PDF | `data-export-overview` 展开全部列/节点 |

## 7. 产品决策（已确认 2026-06-30）

| # | 议题 | 决策 | 实现要点 |
|---|------|------|----------|
| Q1 | 开销字段 | **扩 schema**：`cost_label` + 结构化 `cost` | 前后端、LLM、patch 白名单同步 |
| Q2 | 信息密度 | **默认接近 map.png 详细模式** | 导出 PNG/PDF 为首要场景；`birds-eye` 降为可选辅助，非默认 |
| Q3 | 列内布局 | **水平 LR 链** | 替换现有纵向叠放 |
| Q4 | 同天跨区连线 | **始终绘制** | `OverviewEdgeLayer` 扩展跨区正交路由 |
| Q5 | 节点描述 | **`tips[0]` 作总览摘要** | 不新增 `description` |
| Q6 | 区域行配色 | **按行索引循环 3 色 tint** | 类似 map.png 蓝/黄/绿，低饱和 |
| Q7 | 天气 | **支持手动编辑** + 预留 LLM `fetch_weather` tool | 生成时 LLM 可填；编辑侧栏可改；后续对话拉取 |

### 7.1 决策对 UI/导出的约束

- **总览节点卡**默认展示：类型色块、图标、名称、时间、停留、`cost_label`/`cost`、`tips[0]`、楼层、可选标记。
- **导出**（`data-export-overview`）展开全部列与节点，不做折叠；样式与屏显一致，另备浅底高对比主题（Phase 4）。
- **列内通勤边、跨区边、跨日边**在导出图中均须可见（Q4 始终画）。

**`ItineraryNode` 完整增补（契约原文）**：

```typescript
type CostPer = 'person' | 'total' | 'group';

interface NodeCost {
  amount?: number;
  currency?: string;
  per?: CostPer;
  note?: string;
}

interface ItineraryNode {
  // ...既有字段
  cost_label?: string;
  cost?: NodeCost;
}

type WeatherIcon = 'sunny' | 'cloudy' | 'overcast' | 'rain' | 'storm' | 'snow';
type WeatherSource = 'llm' | 'manual' | 'api';

interface DayWeather {
  temp_min: number;
  temp_max: number;
  icon: WeatherIcon;
  description: string;
  source?: WeatherSource;  // 手动编辑置 manual；未来 API 置 api
}
```

**后端 `form_patch_tool` 增补白名单**：

```python
NODE_SETTABLE_FIELDS = frozenset({
    # ...既有
    "cost", "cost_label",
})

DAY_WEATHER_FIELDS = frozenset({
    "temp_min", "temp_max", "icon", "description",
})

WEATHER_ICONS = frozenset({"sunny", "cloudy", "overcast", "rain", "storm", "snow"})
```

**patch 路径示例**：

```
days[0].nodes[d1-n2].cost_label     → set "约 80 元/人"
days[0].nodes[d1-n2].cost           → set { "amount": 80, "currency": "CNY", "per": "person" }
days[1].weather.temp_min            → set 26
days[1].weather.icon                → set "cloudy"
```

**LLM 生成 prompt 增补要点**（`itinerary_llm.py`）：

- 门票/餐饮/交通等节点尽量输出 `cost` 或 `cost_label`（中文展示）
- 每天输出 `weather`：`temp_min/max`、`icon`、`description`（可基于目的地与季节推断，`source` 默认 `llm`）
- 关键须知写入 `tips[]`，首条作总览摘要

### 7.3 天气：手动编辑 + `fetch_weather` Tool（预留）

#### 7.3.1 手动编辑（Phase 0 实现）

在 `ItineraryEditor` 中，当选中某日且无选中节点时，或增加 **「当日概况」** 区块：

| 表单项 | 字段 | 控件 |
|--------|------|------|
| 最低温 | `weather.temp_min` | number |
| 最高温 | `weather.temp_max` | number |
| 天气图标 | `weather.icon` | 下拉：晴/多云/阴/雨/雷暴/雪 |
| 描述 | `weather.description` | text |
| — | `weather.source` | 用户保存时自动写 `manual` |

列头 `OverviewColumnHeader` 展示：`日期 · 星期 · temp_min~max° · 图标 · description`。

#### 7.3.2 `fetch_weather` Tool（Phase 0 留接口，Phase 2+ 实现）

与现有 `update_trip_request` / `update_itinerary`（`form_patch_tool`）并列，供**对话 supplement 模式**调用。

**工具名**：`fetch_weather`

**触发语义**（用户话术示例）：

- 「帮我查一下 10 月 16 号新加坡天气」
- 「刷新第 2 天天气」

**LLM 输出结构**（parse 层新增 action，非 FormPatch）：

```json
{
  "action": "fetch_weather",
  "day_index": 2,
  "summary": "查询第 2 天（10/18）新加坡天气预报"
}
```

**后端执行流程**（分阶段）：

```
Phase 0（stub）  LLM 根据目的地+日期推断 → 写入 weather，source=llm
Phase 2（API）   调用天气 API（Open-Meteo 等）→ source=api
                 失败时降级 LLM 推断
```

**前端确认流**：

1. `ChatPanel` 展示天气补丁卡片（类似 `PatchConfirmPanel`）
2. 用户确认 → `updateDay(dayIndex, { weather: { ... }, source })`
3. 总览列头即时刷新

**需新增/改动文件（tool 阶段）**：

| 文件 | 职责 |
|------|------|
| `backend/app/services/weather_tool.py` | **新建**：执行查询、返回 `DayWeather` |
| `backend/app/services/chat_parse.py` | system prompt 注册 `fetch_weather` |
| `frontend/src/types/travelPlan.ts` | `FormPatchAction` 或独立 `WeatherFetchPatch` |
| `frontend/src/components/chat/WeatherFetchPanel.tsx` | **新建**：确认 UI |

> **开口设计**：Phase 0 仅实现 schema + 手动编辑 + parse 层 action 占位（可返回「天气查询即将支持」）；tool 执行逻辑与 API 对接放在 Phase 2，不阻塞总览 UI 开发。

### 7.4 区域行 tint 色值（Q6）

按 `regionIndex % 3` 循环，低饱和 tint（参考 map.png）：

| 索引 % 3 | CSS 变量建议 | 色相 |
|----------|-------------|------|
| 0 | `--region-tint-a` | 青蓝 `hsl(205 45% 18%)` |
| 1 | `--region-tint-b` | 琥珀 `hsl(42 40% 16%)` |
| 2 | `--region-tint-c` | 青绿 `hsl(155 35% 15%)` |

应用于 `.overview-cell--alt` 与 `.region-rail__label` 行背景，`color-mix(..., 100%)` 与 `--bg-base` 混合约 8–12%。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 信息过密 | 小屏难读 | 列内横滚；导出仍全量展开（Q2） |
| 列宽固定 | 节点挤出 | `min-width` + 横滚 |
| 跨区边与虚拟化 | 边断裂 | 跨区边用列 x + 行 y 计算，不依赖虚拟化 DOM |
| LLM region 不一致 | 行爆炸 | 后端 prompt 约束 + 前端同义词合并 |
| 锚点与真实 DOM 偏差 | 线错位 | ResizeObserver + 边渲染后置 |
| 开销/天气数据缺失 | 空白 | 字段可选不占位；侧栏可编辑 |
| 前后端契约不同步 | 运行时静默丢字段 | Phase 0 按 §7.2 清单同批改动 |

## 9. 总结

| 维度 | 结论 |
|------|------|
| 布局 | 区域×日期矩阵；列内**水平 LR 链**；跨区/跨日连线**始终绘制** |
| 信息 | 默认 **map.png 详细密度**（服务导出）；`tips[0]` 描述；`cost` 开销 |
| 数据 | Phase 0 **前后端同步** schema（§7.2）；天气手动编辑 + `fetch_weather` 预留 |
| 视觉 | 类别色块 + **行索引 3 色 tint** + 图例 |
| 节奏 | Phase 0 契约 → Phase 1 布局连线 → Phase 2 节点 → Phase 3 分组图例 → Phase 4 导出抛光 |

旧版《视觉优化分析》中的「总览仅 3 字段」建议**已废止**；以本文档及 §7 确认决策为准。
