### P94 · 机场/同日节点时刻未按确认航班硬校准（2026-08-09）✅

**现象**：确认航班 `arrive_at`/`depart_at` 后，行程机场节点与后续景点时间仍可由 LLM 随意填写（如抵达 05:55 却写 10:00，或景点早于出关）；酒店已有日闭环硬校准，航班仅靠 prompt。

**根因**：`enforce_travel_intel_anchors` 只跑 `enforce_confirmed_hotels`；航班仅用于回程日索引（P92），无机场时刻回写与同日接龙。

**修复**

| 层 | 改动 |
|----|------|
| `enforce_confirmed_flights` | 去程日首机场 `start=arrive`、`end=arrive+75m`；回程日末机场 `end=depart`、`start=depart-120m`（早班可过夜窗）；缺节点则注入；`meta.flight_bindings` |
| `align_day_schedules` | 同日按锚点接龙，保停留时长与边间隔；过满则压缩并 `meta.warnings`；早班回程下调晨宿时刻 |
| 入口 / prompt | `hotels → flights → cascade`；HARD 标明服务端再校准 |

**验收**：`python backend/scripts/test_intel_anchor_enforce.py`

**主键文件**：`intel_anchor_enforce.py` · `itinerary_llm.py` · `test_intel_anchor_enforce.py`

**说明**：景点停留仍非营业时间真相源；本项保证机酒锚点自洽与同日不倒序。

### P89 · Chat search_flights 不同步 trip_request 面板（2026-08-09）✅

**现象**：用户对话里已明确出发地/目的地/往返日/人数，并触发搜机票，但计划摘要与机票面板仍是旧值或空（甚至带着过期日期去打 Ignav）。

**根因**：LLM 常只发 `tool_calls.search_flights`，省略对应 `FormPatch`；前端又先搜票后写 patch，导致 `trip_request` / `FlightIntelPanel` 本地字段未更新。

**修复**

| 层 | 改动 |
|----|------|
| Prompt | 提到 OD/日期/人数时必须出 patches；search_flights 不能替代；禁过去年份 |
| 后端 | `_patches_from_search_flights`：从 tool args 合成缺失的 trip_request patches |
| 前端 | 先 apply patches，再执行搜票；`patchesFromSearchFlightsTool` 作兜底 |

**验收**：`python backend/scripts/test_chat_tool_calls.py` · `npx tsx src/utils/flightToolTripSync.test.ts` · 对话搜票后摘要/机票表单显示同组 OD·日期·人数

**主键文件**：`chat_parse.py` · `ChatPanel.tsx` · `flightToolTripSync.ts`
