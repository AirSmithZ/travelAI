### P117 · 片区 geocode 中间层：航班 IATA 围栏锚 + 国家码（2026-08-09）✅

**现象**：`destination=新西兰` 且已确认 `TFU→AKL` 时，`POST /stay-zones/recommend` 返回 200，LLM 正确给出 `city=奥克兰` / Britomart，但 `geometry.center ≈ (39.44, -79.53)`（美国西弗吉尼亚）；真奥克兰命中被 fence 以 ~13700km 拒绝。

**根因**（P113 同族，未覆盖层）
1. P113 已把 bias 字符串从模糊 destination 换成 `zone.city` / 航班抵达城「奥克兰」
2. `resolve_destination_center("奥克兰")` 无 NZ 别名/国家码 → 全球 Top1 落到 Auckland, WV
3. 围栏钉在错误半球后，正确锚点全部 reject；错误圆心仍可能写入 geometry

**修复**
- `GeocodePlaceContext` 中间层：`city_label` + `geocode_destination`（EN+国家）+ `country_code` + **抵达机场 lat/lon**
- `attach_zone_geometry` / `geocode_place` 支持 `center_lat/lng` + `country_code` 钉 fence（优先 AKL 坐标，不再先 geocode「奥克兰」）
- `city_aliases`：奥克兰/新西兰/基督城/皇后镇 → NZ；`_COUNTRY_HUBS` 补 New Zealand
- 前端 `hotelGeocodeCity`：zone.city → 航班抵达城 → destination（`flightArrivalCity.ts`）
- geocode 全失败时 last-resort 用机场坐标，避免错国

**验收**：`PYTHONPATH=. python backend/scripts/test_stay_zone_geocode_bias.py`  
**主键**：`geocode_bias.py` · `enrich.py` · `geocoding.py` · `city_aliases.py` · `StayZonePanel.tsx`

### P113 · 片区几何围栏优先 zone.city / 航班抵达城（2026-08-09）✅

**现象**：`destination=马来西亚海岛` 时，LLM 正确推荐 `city=亚庇 (哥打基纳巴卢)`、`anchor_hints=Jalan Gaya / Jesselton Point`，但 `geometry.center` 落到 `(1.57, 103.81)`（柔佛一带）；片区 lodging / 店名搜索随之空结果。Trip.com 详情页（`cityId=1393`）可找到同一酒店。

**根因**
1. `attach_zone_geometry` 用模糊的 `trip_request.destination` 做 geocode 围栏中心（约 `2.44, 104.52`），未用 `zone.city`
2. 真亚庇锚点被围栏以 ~1300km 拒绝；Photon 在错误围栏内给出假命中
3. 店名搜索前端同样把 `destination` 原样传给 autocomplete

**修复**
- 新增 `resolve_zone_geocode_city`：`zone.city`（≠ destination）→ 航班 outbound `dest_iata` 城市 → fallback
- `attach_zone_geometry` / `rank_anchor_hints` 一律用该 bias 做围栏
- 前端店名搜索：`hotelGeocodeCity` 优先选中/推荐片区的 `city`
- 单测：`scripts/test_stay_zone_geocode_bias.py`

**主键**：`geocode_bias.py` · `enrich.py` · `StayZonePanel.tsx`  
**后续**：国家级 destination + 歧义城名见 **P117 / GEO-12**（IATA 坐标钉围栏）。

### P86 · 地图有计数但圆点全无（2026-08-09）✅

**现象**：badge「第 1 天 · 5 个节点」但地图无圆点；仅一条蓝线悬空。

**根因**：P81 关掉 cluster 图层，但若 source 仍 `cluster: true` 且缺 cluster 层，circle 的 `!point_count` 过滤在城市缩放下会丢掉全部点；路线是独立 source 仍可画。

**修复**：按 style 检测 `cluster` 并强制重建非聚合 source；去掉 circle/label 的 `point_count` 过滤。

**验收**：硬刷新后当日圆点与线端点对齐；切 D1/D2 圆点集合变化

### P81 · 节点坐标重合与连线不准（2026-08-09）✅

**现象**：单日「5 个节点」地图只见 2 个点；连线指到空白或与圆点错位。

**根因**

1. **地理编码塌缩**：中文 POI 对英文命中名称分为 0 → 打分退化成「离目的地中心最近」→ 多个景点落到同一城市中心坐标（成功写入，不是失败回退）
2. **`node.update` 用 provider 标题覆盖节点名**，掩盖错配
3. **MapLibre clusterMaxZoom=14 + fit maxZoom=14**：`spreadMapNodes` 仅 ~60m，仍被聚合成 1–2 个气泡；线画在 feature 坐标上、眼看的是 cluster → 「连到空白」

**修复**

| 层 | 改动 |
|----|------|
| `geocoding.py` | 拒城市中心误命中；名称分&lt;1 不接受；payload 不改写 `name`；塌缩告警 |
| `spreadMapNodes.ts` | 120m 邻域成组、~220m 散开 |
| `TravelMap.tsx` | **关闭节点聚类**；fit maxZoom 16；连线仍用 display 坐标 |

**验收**：`python backend/scripts/test_geocode_collapse.py` · 重新生成并等地理编码完成后刷新地图
