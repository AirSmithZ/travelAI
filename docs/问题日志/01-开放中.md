### P133 · 多城行程体验割裂：单城组合 vs 一步到位（2026-08-12）✅ 策略 A 已落地（MC-1…4 + ORDER）

**现象**：旅行规划整体很割裂；一旦涉及多城（换城航班 + 多地酒店），机酒玩法更像三套工具，而不是一趟行程。

**根因（与「是不是只做了单城」）**：**是（已补城段模型）。** 航班 UI 已能多段追加（B-P3），表单/住宿/生成曾按 **单 `destination`** 闭环——现已按策略 A 切段组合。

| 层 | 单城假设（旧） | 多城（现） |
|----|----------|----------|
| `trip_request` | `destination: string` | +`segments[]` |
| 航班 | 单 OD 搜价 | sequence + `segment_id` / 城际加段 |
| 住宿 | 一城片区锁店 | 需换城→加段；∀段锁店 |
| 生成 | 一个 destination 围栏 | HARD 多段 + 按日 geocode |

文档 [18 §5](../llm-travel-data/18-机酒优先与迭代行程产品决策.md) 早已约定：多城 = 单城逻辑重复应用；Phase 1 不做跨段联合最优。航班大致对齐，**下游未闭合** → 割裂感。

**路线对比**

| | **A. 多个单城组合（推荐）** | **B. 一步到位多城计划** |
|--|---------------------------|------------------------|
| 做法 | Trip = 有序城段；每段自带机酒玩法；段间城际腿 | 一次填多城、一次联合搜、一次全局生成 |
| 优点 | 复用门禁/片区/closed pool；可 scoped 换店；可渐进 | 叙事「一个按钮」 |
| 缺点 | 要城段 UI + schema | 组合爆炸、无联运主 API、放大 P122/P128、难局部重试 |

**建议拍板：A。** 不把 B 当下一里程碑（L3+）。

**落地形状（MC-0→3，详见分析稿）**
1. **MC-0**：UI 明示「当前城段」；多段航班存在时提示本段锁店  
2. **MC-1** ✅（2026-08-12）：`segments[]` + `deriveSegments` + ∀段锁店门禁（FE `planReadiness`/`citySegments` + BE `_require_locked_hotel`）  
3. **MC-2** ✅（2026-08-12）：需换城 →「加为下一段」；`segment_stays` 真多段；加段后可锁店（衔接 P131 目录仍开放）  
4. **MC-3** ✅（2026-08-12）：确认腿写 `segment_id`；城际确认→ensure 加段；下一段/多城模板预填下一城；chat 搜票不覆写 hub destination  
5. **MC-4** ✅（2026-08-12）：HARD 列 `city_segments`/by_segment；`city_for_day` + 按日 geocode 围栏；closed pool 多酒店 Maps；days[].segment_id（衔 P122）

**同批 ORDER min**：`validateSegmentOrder` → readiness softWarnings；城段日期重叠 hard 阻断 generate。气候/visit_window 仍见 [39](../llm-travel-data/39-多城先去哪决策因子.md)。

**波1同批已修**：P128 scoped 换店 · P129 估时/地图标签 · P132 tips 选中展开。

**关联**：P128（换店 scoped）· P131（片区是段内目录）· P122（围栏按城段）· P129（城际禁止假 20min）

| **分析稿**：[37](../llm-travel-data/37-多城割裂与单城组合策略.md) · [38 工程联动](../llm-travel-data/38-多城城段实施影响与联动改动.md) · [39 先去哪/航班序/天气季/日期窗](../llm-travel-data/39-多城先去哪决策因子.md)

**决策层补遗（39）**：锁航后城序冻结；气候/花期/签证等须在订票前建议或事后警告，禁止静默对调城；WX-01 逐日预报只够段内避雨，不够「先去哪」。

### P132 · 节点卡注意事项强制截断（2026-08-12）✅ 已修复（波1）

**现象**：路线图 / 总览节点卡上的「注意事项」（`tips[]`）内容一多就显示不全，只能靠浏览器 `title` 悬停看全文，体验差。

**根因（代码）**

| 层 | 行为 |
|----|------|
| CSS | `.trip-node__desc` 固定 `-webkit-line-clamp: 2`（`TripNode.css`） |
| 渲染 | `TripNode` / `OverviewNodeCard` 把 tips `join(' · ')` 成一段，再被两行夹死 |
| 布局 | `TRIP_NODE_HEIGHT` / dagre 按固定高度排，未随 tips 变高 |
| 数据 | `hotelDayLoop` 仍 `tips.slice(0, 4)`（写入上限，与展示截断叠加） |
| 对照 | 导出态已 `line-clamp: unset`（`OverviewGraphView.css`），说明产品承认「完整可读」需求，日常浏览却反着做 |

**设计约束（design-taste）**：路线图首要是时间/地点/连线清晰；节点卡不宜默认「全文撑开」导致图面炸裂。应 **渐进披露**，而非全局取消 clamp。

**优化方案（推荐组合 · UX-NODE-TIPS）**

1. **默认**：保留 2 行预览 + 末尾「…」；有截断时显示「展开 / N 条注意」
2. **选中态**：当前选中节点取消 clamp，tips 改为 **列表**（每条一行），卡片 `height: auto`；必要时 `updateNodeInternals` / 临时抬高 RF measured height，避免叠边
3. **侧栏完整编辑**：选中即滚动到 `ItineraryEditor` 的 `TipsEditor`（已有全量编辑），卡片展开与侧栏同源，避免双写
4. **勿依赖 hover title**：触控无悬停；title 仅作兜底
5. **可选**：总览单元格已有 `OverviewCellNote`（3 行 clamp）— 长说明优先进单元格 note，节点卡只留短 tip；与 **P130 注意事项看板** 分工：节点 tip = 当场注意，看板 = 行前/习俗

**不建议**：全局去掉 line-clamp 且不调布局（边会穿节点）；把长文塞进 168px 宽卡当主阅读面。

**主键**：`TripNode.tsx` · `TripNode.css` · `OverviewNodeCard.tsx` · `graphLayoutConstants.ts` · `TipsEditor`

### P128 · 换酒店替换了全部日闭环酒店（2026-08-12）✅ 已修复（波1）

**现象**：用户以为「只换当前这家」；实际锁定/店名替换后，行程里**多日首尾酒店节点**都被改成新店名。

**根因（代码）**
1. `confirmStayZoneHotel` / `addStandaloneHotel` → `applyHotelDayLoop(itinerary, hotels, …)`
2. `hotelDayLoop` 按酒店 `check_in/out` 展开 **全程过夜日**，对每个覆盖日 `placeDayHotels` 重写 morning/evening 酒店节点
3. 店名搜索锁定常为 **standalone**（无 `zone_id`），覆盖更广；多酒店时后写的 `dayOwner` 也会覆盖同日

**产品预期**：只更新「当前选中/当前锚定」的那一段住宿（或当前 `zone_id` / `sequence` 覆盖的日期窗），其它已确认酒店不动。

**建议（未做 · HOT-SWAP-01）**
1. 换店入参带 `replace_hotel_id` 或 `scope: current | zone | all`
2. `applyHotelDayLoop` 仅对目标酒店的 overnight 日重写；其它日保留原节点
3. UI 明示：「将替换 Day2–4 的住宿闭环」可勾选范围

**主键**：`hotelDayLoop.ts` · `usePlanStore.ts` confirm/addStandaloneHotel

### P129 · 通勤仍见 20min 死数据 + 地图无距离（2026-08-12）✅ 已修复（波1）

**现象**：总览/边上仍常出现 **20 分钟**；地图路线无距离标注；拖拽/改连线后两点距离不刷新。  
（P126 只改了总览标签格式；**无 `distance_meters` 时仍只剩时长**，且地图层未接。）

**根因**
| 来源 | 行为 |
|------|------|
| LLM generate | 常写 `walk` + 估时 |
| `hotelDayLoop.reconnectPrimary` | **写死** `duration_minutes: 20`（换店后整日边重连） |
| `intel_anchor_enforce` 重建边 | 同样默认 **walk / 20** |
| TRN-02 可疑边补算 | 仅部分边；短距/已非默认时长可能跳过 |
| `TravelMap` | 只画 polyline，**无距离/时长 label** |
| 改边 / 换节点 | 未触发对该边的 Directions / 直线重算 |

**建议（未做 · TRN-05）**
1. 禁止「静默 20」：重建边时用 haversine 估步行/打车，并标 `route_source=estimate`；有坐标则入队 Directions
2. **地图**：route 中点标 `800m · 12′`（与总览同一套 `commuteLabels`）
3. **总览表格**：边变更 / 节点坐标变更 → 对该边 `POST /commute/lookup` 或本地估时后写回
4. 换店 `reconnectPrimary` 不得再硬编码 20

**主键**：`hotelDayLoop.ts` · `intel_anchor_enforce.py` · `TravelMap.tsx` · `EdgeEditor` · TRN-02 enrich
