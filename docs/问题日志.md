### P94 · 机场/同日节点时刻未按确认航班硬校准（2026-08-09）✅

**现象**：确认航班 `arrive_at`/`depart_at` 后，行程机场节点与后续景点时间仍可由 LLM 随意填写（如抵达 05:55 却写 10:00，或景点早于出关）；酒店已有日闭环硬校准，航班仅靠 prompt。

**根因**：`enforce_travel_intel_anchors` 只跑 `enforce_confirmed_hotels`；航班仅用于回程日索引（P92），无机场时刻回写与同日接龙。

**修复**

| 层 | 改动 |
|----|------|
| `enforce_confirmed_flights` | 去程日首机场 `start=arrive`、`end=arrive+75m`；回程日末机场 `end=depart`、`start=depart-120m`（早班可过夜窗）；缺节点则注入；`meta.flight_bindings` |
| `align_day_schedules` | 同日按锚点接龙，保停留时长与边间隔；过满则压缩并 `meta.warnings`；早班回程下调晨宿时刻 |
| 入口 / prompt | `hotels → flights → cascade`；HARD 标明服务端再校准 |

**验收**：`python backend/scripts/test_intel_anchor_enforce.py`

**主键文件**：`intel_anchor_enforce.py` · `itinerary_llm.py` · `test_intel_anchor_enforce.py`

**说明**：景点停留仍非营业时间真相源；本项保证机酒锚点自洽与同日不倒序。

### P93 · thinking 截断 + 前端假完成「正在写入」（2026-08-09）✅

**现象**：SSE `completion_tokens=8000`、`content_chars=0`、`validate/fixing`；UI 显示「AI 生成完成，正在写入…」像卡住。

**根因**：DeepSeek V4 默认 thinking，与 content 共用 `max_tokens`；前端在 `phase=llm` 且已有耗时就写「生成完成」。

**修复**：generate/fix 传 `thinking: disabled`；截断修复改用 flash；前端识别 `validate` →「正在修复校验…」，不再假完成。

**主键文件**：`llm_client.py` · `itinerary_llm.py` · `ChatStatusBar.tsx` · `usePlanStore.ts`

### P90 · generate/stream 截断后 `_LLMItinerary.title` missing（2026-08-09）✅

**现象**：SSE `llm` 完成（`completion_tokens≈3500`）→ 两次 `validate/fixing` → `error: Field required title … input_value={}`。

**根因**

1. 默认 `LLM_MAX_TOKENS_GENERATE=3500`，4 日行程 + reasoning 模型易 `finish_reason=length`，流式 `content` 为空  
2. `chat_json*` 用 `content or "{}"` 把空回复当成合法 JSON  
3. 修复轮仍打满 token，再次得到 `{}`；Pydantic 报缺 `title`（表象）  
4. Prompt「每天 6–9 节点」与修复提示「3–6」不一致，输出偏胖

**修复（llm-api-engineering）**

| 层 | 改动 |
|----|------|
| 配置 | 默认 generate `max_tokens` → **8000**（`.env.example` 同步） |
| LLMClient | 空 content **抛错**，记录 `finish_reason`；禁止 `or "{}"` |
| Prompt | 每天 **4–6** 节点；禁止空对象 `{}` |
| 修复轮 | 与主生成同档 token；截断提示要求短完整 JSON；**最多 1 次**修复；`_require_itinerary_raw` 拒绝 `{}`/缺 title |

**验收**：`python backend/scripts/test_itinerary_llm_tokens.py` · 重启 backend 后重新 generate（若 `.env` 曾写死 3500 需改为 ≥8000）

**主键文件**：`llm_client.py` · `itinerary_llm.py` · `config.py`

### P84 · 松手后实线错位、滚动才对齐（2026-08-09）✅

**现象**：拖完节点后跨区实线端点有时对不准节点；一滚动总览又跳回正确位置。

**根因（交互一致性）**：`useOverviewNodeAnchors` 的 revision 原先只看「节点个数 / 天数 / 区域数」。松手写入 `overview_offset` 后 layout 坐标已变，但 revision 不变 → 不重新 `measure()`。`ResizeObserver` 只对尺寸变化敏感，**绝对定位的 left/top 移动不会触发**；滚动监听会 `measure()`，所以一滚就修好。期间 stale DOM 锚点仍覆盖正确的 `matrixPlacements`。

**修复**：`anchorRevision` 纳入各节点 `x/y` 指纹，拖拽提交后强制重测。

**验收**：跨区拖节点松手 → 实线立即贴边，无需滚动

### P83 · 总览拖拽跨区实线不同步（2026-08-09）✅

**现象**：拖节点时同格虚线跟手，跨区实线（如酒店↔餐厅）停在原点，交叉/卡顿感明显。

**根因**：跨区边走 `OverviewEdgeLayer`，OV-01 DOM 锚点量到的是原地 `ghost-source`，盖住了 `liveMatrixPlacements` 的幽灵坐标；同格边用 `edgeDragPreview` 增量，故虚线正常。

**修复**：拖拽中跳过活跃节点的 DOM 锚点覆盖；幽灵卡片不注册 `data-overview-node`。

**验收**：拖动跨区主链节点 → 实线端点跟幽灵（同格虚线行为不变）

### P81 · 节点坐标重合与连线不准（2026-08-09）✅

**现象**：单日「5 个节点」地图只见 2 个点；连线指到空白或与圆点错位。

**根因**

1. **地理编码塌缩**：中文 POI 对英文命中名称分为 0 → 打分退化成「离目的地中心最近」→ 多个景点落到同一城市中心坐标（成功写入，不是失败回退）
2. **`node.update` 用 provider 标题覆盖节点名**，掩盖错配
3. **MapLibre clusterMaxZoom=14 + fit maxZoom=14**：`spreadMapNodes` 仅 ~60m，仍被聚合成 1–2 个气泡；线画在 feature 坐标上、眼看的是 cluster → 「连到空白」

**修复**

| 层 | 改动 |
|----|------|
| `geocoding.py` | 拒城市中心误命中；名称分&lt;1 不接受；payload 不改写 `name`；塌缩告警 |
| `spreadMapNodes.ts` | 120m 邻域成组、~220m 散开 |
| `TravelMap.tsx` | **关闭节点聚类**；fit maxZoom 16；连线仍用 display 坐标 |

**验收**：`python backend/scripts/test_geocode_collapse.py` · 重新生成并等地理编码完成后刷新地图

### P61–P66 · 地理编码 autocomplete 专项（2026-06-29）✅

**原现象**：`GET /geocode/autocomplete?q=哥打基纳巴卢国际机场&city=亚庇` → `{"results":[]}`。

**根因**

1. 仅 Nominatim 单源，当前环境 **403 Forbidden**
2. Photon 未带 **User-Agent** 时同样 403（httpx 默认 UA 被拒）
3. 异常被 `return []` 吞掉，HTTP 200 误导前端
4. `city=亚庇` 无英文别名归一
5. 前端需手动点按钮，无 debounce 联想

**修复**

| # | 要点 | 文件 |
|---|------|------|
| P61 | Provider 链 `photon,nominatim` 回退；Photon/Nominatim 均带 `GEOCODE_USER_AGENT` | `geocode_providers.py`, `config.py` |
| P62 | 全源失败 → `502` + `GeocodeProviderError`；真无结果 → `warnings` | `geocode.py`, `geocode_providers.py` |
| P63 | `GeocodeProvider` 抽象 + `GEOCODE_PROVIDERS` / `PHOTON_BASE_URL` / `NOMINATIM_BASE_URL` | `geocode_providers.py`, `config.py` |
| P64 | `city_aliases.py`：`亚庇` → `Kota Kinabalu, Malaysia`；多 query 变体 | `city_aliases.py`, `geocoding.py` |
| P65 | `NodeCoordEditor` 输入 debounce 400ms 自动联想 + 候选列表 | `NodeCoordEditor.tsx` |
| P66 | `GeocodeApiError` 展示上游 502；空结果区分 `warnings` vs 服务失败 | `geocode.ts`, `NodeCoordEditor.tsx` |

**响应扩展**

```json
{
  "results": [...],
  "provider": "photon",
  "warnings": []
}
```

**验收**

```bash
# 后端实测（2026-06-29）

npm run build ✅
```
