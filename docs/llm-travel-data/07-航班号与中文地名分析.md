## 1. 问题概述

| # | 问题 | 现状 | 可行性 |
|---|------|------|--------|
| 1 | `/api/v1/flights/search` 能否返回航班号并在前端展示？ | API 与前端类型均无 `flight_numbers`；Ignav segment 有数据但未提取 | ✅ **可行**，改动集中在 schema + normalize + UI |
| 2 | 前端做中文地名转换 | 界面显示 IATA 三字码（如 `PVG→SIN`）；后端 `city_codes.json` 仅用于**搜索入参**解析 | ✅ **可行**，需前端（或 API）增加展示用映射 |

## 2. 问题一：航班号

### 2.1 当前数据流

```
用户输入 origin/destination/date
    ↓
POST /api/v1/flights/search  (backend/app/api/v1/flights.py)
    ↓
search_flights()  (backend/app/services/flight/search.py)
    ├─ resolve_tripcom_city_code / resolve_search_iata  (city_codes.py)
    ├─ search_ignav()  → normalize_ignav_itinerary()  (ignav_provider.py)
    ├─ rank_offers()
    └─ FlightSearchResponse { ranked: FlightQuote[] }
    ↓
frontend searchFlights()  (frontend/src/api/flights.ts)
    ↓
FlightIntelPanel 渲染 ranked[]
    ↓
confirmFlightQuote → flightLegFromQuote → ConfirmedFlightLeg
```

### 2.2 后端：`FlightQuote` 无航班号字段

`backend/app/schemas/flight.py` 中 `FlightQuote` 当前字段：

| 字段 | 说明 |
|------|------|
| `id`, `origin_iata`, `dest_iata` | 标识与起终点（搜索级 IATA） |
| `airline`, `route_label` | 航司名、航线路径（如 `PVG→SGN→SIN`） |
| `depart_time`, `arrive_time`, `duration_minutes`, `stops` | 时间与经停 |
| `price_*`, `source`, `confidence`, `rank*` | 价格、来源、排序 |

**没有** `flight_numbers` 或等价字段。

### 2.3 Ignav 源：航班号已存在于 segment

根据 [Ignav Response Format](https://ignav.com/docs/response-format)，每个 `outbound.segments[]` 包含：

| Ignav 字段 | 类型 | 示例 |
|------------|------|------|
| `marketing_carrier_code` | string \| null | `"AA"` |
| `flight_number` | string \| null | `"100"` |
| `operating_carrier_name` | string \| null | `"American Airlines"` |
| `departure_airport` / `arrival_airport` | string | `"PVG"` / `"SIN"` |

`normalize_ignav_itinerary()`（`backend/app/services/flight/ignav_provider.py`）目前只从 segment 提取：

- 机场码 → `route_label`（`_leg_label`）
- 起降时间 → `depart_time` / `arrive_time`
- 航司 → `airline`（优先 `outbound.carrier`，否则 `operating_carrier_name` / `marketing_carrier_code`）

**未读取** `flight_number` / `marketing_carrier_code` 组合。

单元测试样例（`backend/scripts/test_flight_ignav_parse.py`）的 segment 也**未包含**航班号字段，与真实 API 响应不一致。

### 2.4 LetsFG 源：大概率无航班号

`letsfg_provider.py` 从 CLI 表格解析：航司名、航线文字、起降时间、时长、经停、价格。**无航班号列**。若启用 LetsFG fallback，`flight_numbers` 应为空数组或省略。

### 2.5 前端：类型与 UI 均未展示航班号

**类型层**

- `frontend/src/types/flight.ts` — `FlightQuote` 无 `flight_numbers`
- `frontend/src/types/travelIntel.ts` — `ConfirmedFlightLeg` **已有** `flight_numbers?: string[]`（与方案文档 06 对齐），但 `flightLegFromQuote()` **未赋值**

**UI 层**（`FlightIntelPanel.tsx` 推荐卡片）

当前展示：`#rank` · `airline` · `price` · 时间 · 时长 · 经停

未展示：`route_label`、航班号

**已确认航段摘要**（`formatFlightLegSummary`）：

```
去程 · PVG→SIN · Spring · USD 126
```

同样无航班号。

**开发页** `FlightVerifyApp.tsx` 的 `OfferRow` 也未展示航班号或 `route_label`。

### 2.6 结论：能否返回并渲染？

| 层级 | 结论 |
|------|------|
| **数据源** | Ignav ✅ 有；LetsFG ❌ 无 |
| **API** | ❌ 当前不返回；**加字段即可** |
| **前端类型** | ❌ `FlightQuote` 缺字段；`ConfirmedFlightLeg` 已预留 |
| **前端 UI** | ❌ 未渲染；**加展示即可** |

**答案：可以。** 主路径（Ignav）数据完备；需在 normalize 层提取、schema 透传、前端渲染三处补齐。

### 2.7 推荐实现方案

#### 2.7.1 Schema 设计

在 `FlightQuote` 增加：

```python
flight_numbers: list[str] = Field(default_factory=list)
# 示例: ["9C8549"] 或 ["VJ813", "VJ977"]（经停多段）
```

格式化规则（建议）：

```text
segment_flight = f"{marketing_carrier_code}{flight_number}"
# marketing_carrier_code 或 flight_number 为空时，仅用非空部分或跳过该段
```

往返票：当前 `search_ignav` 仅 normalize `outbound`；若未来支持往返 ranked，需同时处理 `inbound.segments`。

#### 2.7.2 后端改动点

| 文件 | 改动 |
|------|------|
| `backend/app/schemas/flight.py` | `FlightQuote` 增加 `flight_numbers` |
| `backend/app/services/flight/ignav_provider.py` | 新增 `_segment_flight_numbers(segments)`，在 `normalize_ignav_itinerary` 中赋值 |
| `backend/scripts/test_flight_ignav_parse.py` | 样例 segment 补全 `marketing_carrier_code` / `flight_number` 并断言 |
| `backend/app/services/flight/intent_parse.py` | `_compact_offers` 可选增加 `flight_numbers` 供 LLM 推荐 |

#### 2.7.3 前端改动点

| 文件 | 改动 |
|------|------|
| `frontend/src/types/flight.ts` | `FlightQuote.flight_numbers?: string[]` |
| `frontend/src/types/travelIntel.ts` | `flightLegFromQuote` 写入 `flight_numbers: quote.flight_numbers` |
| `frontend/src/components/flight/FlightIntelPanel.tsx` | 卡片 meta 行增加航班号（无则隐藏） |
| `frontend/src/types/travelIntel.ts` | `formatFlightLegSummary` 含航班号，如 `9C8549` |
| `frontend/src/dev/FlightVerifyApp.tsx` | 表格列可选增加「航班号」 |

#### 2.7.4 UI 展示建议

```
#1  Spring                    USD 126
09:30 → 15:10 · 5h40m · 直飞 · 9C8549
[确认选用]
```

经停示例：

```
VJ813 / VJ977 · 1 停
```

#### 2.7.5 风险与注意

| 项 | 说明 |
|----|------|
| `flight_number` 可为 null | Ignav 文档标注 Yes 但允许 null；需容错，空则 `flight_numbers: []` |
| 参考价非预订确认 | UI 仍应标注「以 Trip.com 为准」；航班号用于识别参考班次 |
| 排序去重 | `search.py` 去重 key 为 `(airline, price, duration, stops)`；加航班号后同价同航司不同班次不会被误合并（当前已可区分） |
| LetsFG | 保持 `flight_numbers: []`，前端无数据时不展示 |

## 3. 问题二：中文地名转换

### 3.1 当前行为

**搜索入参（后端 ✅）**

`FlightSearchRequest.origin/destination` 支持 IATA、中文、别名（见 schema 描述）。  
`backend/app/services/flight/city_codes.py` + `data/city_codes.json`：

- 中文/别名 → Trip.com 城市码（如「上海」→ `sha`，「浦东」→ `sha`）
- `resolve_search_iata()` → 大写 IATA 供 Ignav（如 `SHA` / `PVG` 均映射到上海）

**展示出参（前端 ❌）**

| 位置 | 当前显示 | 用户期望 |
|------|----------|----------|
| 已确认航段 `formatFlightLegSummary` | `PVG→SIN` | `浦东→新加坡` 或 `上海→新加坡` |
| 搜索结果卡片 | 仅时间/航司/价格，未显示 `route_label` | 若显示航线，应为中文 |
| 表单 placeholder | `上海 / SHA` | 已提示中文，但结果区仍是 IATA |

前端**没有任何** `city_codes` 或 IATA→中文 的映射文件或工具函数。

### 3.2 现有 `city_codes.json` 能力与缺口

路径：`backend/app/services/flight/data/city_codes.json`

结构：Trip.com **城市码** 为 key，含 `label`（中文城市名）与 `aliases`（IATA/中文别名）。

覆盖约 30 个常用城市/区域（上海、新加坡、东京、曼谷等）。

**缺口：**

| 缺口 | 示例 | 影响 |
|------|------|------|
| 机场码 vs 城市码 | `route_label` 为 `PVG→SGN→SIN`，其中 `SGN`/`HAN` 等 | 需 **IATA 机场码 → 中文** 映射，不能只用城市码 |
| 未收录机场 | `HAN`（河内）不在 json 中 | 应 fallback 显示原 IATA |
| 多机场同城 | PVG/SHA 均属上海 | 可显示「浦东(PVG)」或统一「上海」 |
| 数据单点 | 仅 backend 有 json | 前端需同步副本或 API |

`city_label(code)` 仅在后端 Python 使用，**未暴露 HTTP 接口**。

### 3.3 `route_label` 与 `origin_iata` 的差异

| 字段 | 来源 | 示例 |
|------|------|------|
| `origin_iata` / `dest_iata` | 用户搜索解析后的起终点 | `PVG` / `SIN`（可能与输入别名有关） |
| `route_label` | Ignav segment 实际机场链 | `PVG→HAN→SIN`（经停越南） |

中文转换应优先作用于 **`route_label` 各段** 及 **`origin_iata`/`dest_iata`**，经停场景不能只译起终点。

### 3.4 结论：前端能否做中文转换？

**可以**，且与后端搜索解析解耦：展示层独立映射即可，不影响 Ignav/Trip.com 请求参数（仍用 IATA）。

### 3.5 推荐实现方案

#### 方案 A：前端静态映射（推荐 MVP）

| 步骤 | 说明 |
|------|------|
| 1 | 从 `city_codes.json` 生成或 hand-copy 为 `frontend/src/data/airportLabels.ts` |
| 2 | 扩展映射：**机场 IATA → 中文**（不仅城市码） |
| 3 | 工具函数 `formatAirportLabel(iata: string): string` |
| 4 | `formatRouteLabel(route: string): string` 解析 `A→B→C` 并逐段转换 |
| 5 | 在 `FlightIntelPanel`、`formatFlightLegSummary` 中使用 |

映射表示例：

```typescript
const AIRPORT_LABELS: Record<string, string> = {
  PVG: '浦东',
  SHA: '虹桥',
  SIN: '新加坡',
  SGN: '胡志明市',
  HAN: '河内',
  // ...
};

export function formatAirportLabel(code: string): string {
  const key = code.trim().toUpperCase();
  return AIRPORT_LABELS[key] ?? key;
}

export function formatRouteLabel(route: string): string {
  return route
    .split('→')
    .map((seg) => formatAirportLabel(seg.trim()))
    .join('→');
}
```

**优点**：无额外请求、与现有 backend json 一致、实现快。  
**缺点**：双份数据需同步；冷门机场 fallback 为 IATA。

#### 方案 B：API 返回已翻译 label

在 `FlightSearchResponse` 或每个 `FlightQuote` 增加：

```typescript
origin_label?: string;
dest_label?: string;
route_label_zh?: string;
```

后端 `search_flights` 在 rank 后调用 `city_label` / 新 `airport_label(iata)` 填充。

**优点**：单一数据源、前端简单。  
**缺点**：需新 airport 索引；前端离线/缓存场景仍可能需要本地 fallback。

#### 方案 C：独立 lookup API

`GET /api/v1/flights/labels?codes=PVG,SIN`

**优点**：映射集中维护。  
**缺点**：多一次请求；对当前单一 Panel 略重。

#### 推荐组合

**Phase 1**：方案 A（前端 `airportLabels.ts` + 工具函数），从现有 `city_codes.json` aliases 推导机场映射并手工补全经停常见码（HAN、ICN 等）。  
**Phase 2**（可选）：方案 B，search 响应附带 `route_label_zh`，减少双份维护。

### 3.6 UI 改造建议

**搜索结果卡片** — 增加航线行（中文）：

```
#1  Spring                    USD 126
上海浦东 → 新加坡 · 09:30–15:10 · 5h40m · 直飞 · 9C8549
```

**已确认航段**：

```
去程 · 上海浦东→新加坡 · Spring · 9C8549 · USD 126
```

**表单**：搜索仍接受中文/IATA；可选在 blur 时显示「将搜索：上海(sha)」提示（低优先级）。

### 3.7 数据维护建议

| 项 | 建议 |
|----|------|
| 源文件 | 以 `backend/.../city_codes.json` 为 canonical，或拆出 `airport_codes.json` |
| 同步 | 构建脚本 `scripts/sync-airport-labels.mjs` 生成前端 TS |
| Fallback | 未知 IATA 原样显示，不阻塞渲染 |
| 港澳台/多语言 | 当前 json 已含「香港」；保持与产品语言一致（简体） |
