## 1. 当前用户路径（三股拧在一起）

```text
A 粗推片区 → 确认片区 →「搜索片区酒店」(RollingGo/Trip) → 锁定
B 顶栏「店名搜索」→ geocode 候选 → 锁定（可不绑 zone）
C 地图钉：仅点选 A/B 已有结果（无搜索框）
```

| 入口 | 组件 | 数据源 |
|------|------|--------|
| 店名搜索 | `ZoneHotelNameSearchModule` | geocode autocomplete |
| 片区订房 | `ZoneAreaLodgingModule` | `POST /stay-zones/lodging` |
| Trip / RollingGo 深链 | 片区卡 + lodging 行 | 站外浏览 |
| 地图钉 | `stayHotelMapPins` → `TravelMap` | 只回传选中 draft |

两套列表都叫「锁定此酒店」，认知重复（P110/P112 拆开了嵌套，**没拆认知负担**）。

## 2. 「只能选一家」：数据允许多，产品动作不允许

### 2.1 已具备的多酒店能力

- `ConfirmedHotelStay[]`：`sequence` / `check_in`–`check_out` / `is_primary` / `zone_id?`
- `applyHotelDayLoop`：按入住区间把酒店钉到不同天
- `hotelStayValidate`（B-P6-01）：缺口/重叠软警告
- `primaryHotelOverview`（B-P6-02）：总览主酒店高亮
- 文档 [06](./06-机酒确认与行程生成流程方案.md)：同城换店、多城各一家是设计目标

### 2.2 实际锁店语义 = 替换槽位

| 动作 | 行为 |
|------|------|
| `addHotelFromZone` | 同 `zone_id` **先删后加** → 每片区最多 1 家 |
| `addStandaloneHotel` | 非 zone 酒店 **只保留一家** |
| UI | `.find(h => h.zone_id === zone.id)`、文案「当前锁定」单数 |
| 入住日 | 多抄 trip/zone 整段日期 → 多 zone 易重叠警告 |

**可勉强「多酒店」的方式**：确认多个片区、各锁一家 —— 但无「再加一段住宿」CTA，也无分入住日编辑，主路径仍是单城单店。

## 3. 换店 / 地图困难：生成后面板被踹掉

```text
InputPanel:
  phase === 'detailed' → 强制 leftPanelMode 离开 stay/flight
  showStay = stay && phase !== 'detailed'
StayZoneToolbarButton: detailed 时 return null
PlanSummary「换一家酒店」→ open_stay → 立刻被踢回 chat
```

后果：

1. 玩法生成后 **没有** 店名搜索 / 片区搜店 / 住宿地图钉工作台  
2. 地图上若只剩行程酒店节点，只能靠节点坐标编辑，**不是搜店**  
3. 住宿面板打开时：地图点选只改 draft；**点已锁钉不会进入「搜索替换」**；换片区后他区候选钉会消失  

用户体感「在酒店面板切换酒店却搜不了」= **编辑态缺搜索** + **生成后整块住宿 UX 不可达**。

## 4. 后端 / Agent 加重混乱的点

| 点 | 影响 |
|----|------|
| lodging 空/429 → Trip-first | 「附近没店」错觉；再推去店名搜，双路径更绕 |
| 片区搜 = hub+radius；店名搜 = geocode | 结果集合/坐标质量不一致 |
| 无「添加住宿段」API/工具 | Agent/对话无法驱动 B-P6 多段 |
| `is_primary` ≈ `sequence === 1` | 多店时用户改不了主酒店 |
| Chat/摘要写「换一家」却打不开面板 | 文案与门闩冲突（detailed） |
| P123 人数≠房间 | 询价结构错，加重「搜出来不准」 |

## 5. 值得优化的点（优先级）

### 5.1 用户体验

| ID | 项 | 说明 |
|----|-----|------|
| **HOT-UX-01** | **生成后仍可打开住宿面板** | 取消/放宽 `phase==='detailed'` 对 stay 的强制关闭；工具栏与摘要「换酒店」可用 |
| **HOT-UX-02** | **换店工作台 = 搜店 + 地图** | 住宿态或选中酒店节点时，侧栏常驻店名搜索（复用 `ZoneHotelNameSearchModule`）；明确「替换当前」 |
| **HOT-UX-03** | **锁钉可点 → 替换流** | 点击 `locked:*` 钉打开替换：预填名/进搜索，而不是无响应 |
| **HOT-UX-04** | **双路径收敛文案** | 主路径「在片区附近找」+ 次路径「知道店名」；统一「替换 / 再锁一家」动词 |
| **HOT-UX-05** | **已锁定酒店单一列表** | 卡片内外拆开展示合并为一块「已锁定」，减少重复 |
| **HOT-UX-06** | **多段入住 UI** | 「添加第二段住宿」+ 每段 check_in/out；接 B-P6 警告到主流程 |

### 5.2 Store / 逻辑

| ID | 项 | 说明 |
|----|-----|------|
| **HOT-UX-07** | 拆 `replaceHotel` vs `addHotelStay` | 停止静默按 zone/standalone 覆盖；替换要确认 |
| **HOT-UX-08** | 主酒店可点选 | `is_primary` 用户可改，不只 sequence===1 |
| **HOT-UX-09** | 换店后 dirty / 日闭环 | 有行程时 `applyHotelDayLoop` + dirty banner（已有部分，需面板可达） |

### 5.3 后端 / Agent

| ID | 项 | 说明 |
|----|-----|------|
| **HOT-BE-01** | 空 lodging 永远给下一步 | Trip CTA +「改用店名搜索」同屏，禁伪「附近无店」加强（已有 Trip-first，文案/入口再收紧） |
| **HOT-BE-02** | 地图中心/选点附近搜 | lodging 不绑死 zone hub；支持 map center / 钉旁搜 |
| **HOT-BE-03** | Chat tool：`lock_hotel` / `add_hotel_stay` | 对话「换一家」生成后可执行 |
| **HOT-BE-04** | P123 人数 vs 房间 | 询价与深链参数对齐（已有开放项） |
