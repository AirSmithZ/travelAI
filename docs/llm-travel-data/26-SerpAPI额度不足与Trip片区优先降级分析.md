## 0. 结论摘要

| # | 结论 |
|---|------|
| 1 | **方案合理**，作为 SerpAPI lodging（HOT-02）耗尽时的 **Phase 1 降级主路径**；且比硬撑 Maps 429 更贴 [18 B7/C9](./18-机酒优先与迭代行程产品决策.md)。 |
| 2 | 「用 Trip 搜索」应理解为 **深链跳转 Trip 列表（按城 + 片区 keyword）**，**不是** App 内爬取/伪装库存 API（合规与 [02](./02-酒店信息.md) 已否）。 |
| 3 | 「按区域排列」= **先确认/展示 StayZone → 每区一条 Trip 深链 → 用户从 Trip 选店或回 App 手输/店名 geocode 锁定**；有坐标的候选再 **归入最近片区** 排序展示。 |
| 4 | 「地图标记区域轮廓」= **硬需求**：推荐片区后必须可见 fill+描边；无 geometry 不得假装「已推荐可搜店」。与 P122「酒店区 vs 玩法区」可视化也一致。 |
| 5 | SerpAPI 有额度时可作 **增强**（片区内候选钉）；无额度时 **关闭/跳过** `POST /stay-zones/lodging`，UI 切 Trip-first，避免空列表被当成「附近无酒店」。 |

**一句话**：合理降级 = **片区轮廓（图）+ Trip 深链（搜/订）+ 人确认锁店**；不合理的是把 Trip 网页结果当结构化库存拉进 App。

## 1. 现状与缺口

| 能力 | 现状 | Serp 额度不足时 |
|------|------|----------------|
| 片区推荐 | `recommend_stay_zones` + `attach_zone_geometry` | 仍可用（不依赖 Serp lodging） |
| 片区轮廓上图 | `stayZoneGeoJSON` fill/line（已有） | **须保证有 geometry 才进搜店流**；圆心错则轮廓错（GEO-11/12） |
| 片区内候选列表 | SerpApi Maps → `ZoneAreaLodgingModule` | **易 429/空**；不宜再作为唯一入口 |
| Trip | `build_tripcom_hotel_url(city, dates, area_keyword, highPrice)` | **已有**；降级时应抬成主 CTA |
| 店名搜索 | autocomplete geocode（非 Serp lodging） | 可作锁店补充（用户从 Trip 抄店名） |
| 库存/房价列表 | Phase 1 **明确无**（B7） | 不因本方案新增 |

```text
当前（额度够）：片区 → Serp 附近酒店钉 → 人锁店 →（旁路）Trip 深链
降级（额度不够）：片区 → 地图轮廓必显 → 每区 Trip 深链搜 → 人回 App 锁店名/钉
```

## 2. 用户提案拆解与合理性

### 2.1 「暂时使用 Trip 的搜索酒店功能」

| 解读 | 是否采纳 |
|------|----------|
| 每片区生成 Trip `hotels/list` 深链（city + keyword=片区 + 日期 + 预算） | ✅ **采纳** |
| App 内嵌入 Trip 结果列表 / 爬虫 / Apify 生产拉数 | ❌ 与 B7、[02] 冲突；暂不立项 |
| Hotelbeds / Partner API 临时代替 | ⏸ 商务 `HOT-01`，非「暂时」 |

与已拍板 **C9「酒店 = Trip 深链」** 一致；HOT-02 Serp 列表本是增强，额度没了应退回 C9 主叙事。

### 2.2 「搜索出来的酒店再按区域排列」

在 **无 Trip 结构化回传** 的前提下，可行定义为：

1. **区域为第一排序键**：UI 按 `recommended_stay_zones` 分组（已确认区优先），每组下是该区 CTA + 已锁定/手输候选。  
2. **有 lat/lng 的候选**（店名 geocode、或日后恢复的 Serp）：按距该区 hub / 是否在 contour 内排序（现有 haversine 逻辑可复用，数据源换掉即可）。  
3. **不能**假装「已从 Trip 拉回 N 家再聚类」——没有坐标列表则只做 **区分组展示 + 深链**，文案诚实：「在 Trip 按本片区关键词浏览，选定后回 App 锁定」。

这样「区域排列」是 **产品信息架构**，不是未实现的 Trip 库存排序 API。

### 2.3 「地图上标记区域轮廓」

| 点 | 说明 |
|----|------|
| 为何必要 | 降级后 App 内酒店钉变少，**轮廓是用户理解「住哪一带」的主视觉**；也便于对照玩法钉（P122） |
| 已有基础 | `ensureStayZoneLayers` + circle→polygon fill/line |
| 缺口 | geometry 失败时仍可能推搜店；轮廓弱感知；多区时选中态/图例不足 |
| 降级验收 | 推荐成功且 `status≠rejected` 的区 **必须** 上图轮廓；无轮廓 → warning + 禁止该区「附近搜店」叙事，仅保留城级 Trip 深链 |

## 3. 建议产品流（降级模式）

```text
确认航班（城 OD）
  → 推荐 StayZone（LLM/启发式 + GEO-11/12 钉圆心）
  → 地图：各区轮廓 + 选中高亮（硬门禁）
  → 用户确认片区
  → 主 CTA：「在 Trip 查看该片区酒店」→ 深链（禁自动跳转）
  → 用户从 Trip 选定后：App 内店名搜索 / 粘贴锁定 → intel.hotels
  →（可选）若 SERPAPI 恢复：同区再开 lodging 候选钉，作增强非必须
```

**文案**：明确「列表在 Trip；App 负责片区与锁定」，避免「附近无酒店」误报（P118 类）。

## 4. 风险与边界

| 风险 | 缓解 |
|------|------|
| 深链 city/keyword 不准 → Trip 空或偏城 | 深链优先 `zone.city` EN + 航班抵达城；keyword 用短地名非中文 slogan |
| 无 App 内钉 → 锁店坐标弱 | 锁店必须走 geocode（店名模块）；失败则低信心 + 地图点选 |
| 用户以为 App 仍「搜到了价」 | UI 不展示伪房价；价只在 Trip |
| 轮廓圆心错（国家级 destination） | 继续依赖 GEO-11/12；与 P122/GEO-13 分列，本方案不替代玩法围栏修复 |
| 合规爬 Trip | **不做** |
