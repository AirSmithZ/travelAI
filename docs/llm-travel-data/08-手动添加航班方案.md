## 1. 问题定义

### 1.1 用户场景

| 场景 | 说明 | 现有能力 |
|------|------|----------|
| **A. 先搜后订（App 内）** | Ignav 查价 → 对比 → 确认 → 跳转 Trip.com 付款 | ✅ 主路径 |
| **B. 先订后补（Trip / 航司）** | 用户已在 Trip.com 买好票，回来填航段让行程对齐时刻 | ❌ 无入口 |
| **C. Ignav 搜不到** | 报价空、超时、或班次与用户实际购买不一致 | ⚠️ 仅提示打开 Trip.com |
| **D. 往返 / 多段部分手工** | 去程 Ignav 确认，回程自己在 OTA 订 | ❌ 回程无法单独手填 |
| **E. 玩法先行后补锚点** | 已 generate，事后补上真实航班约束 | ❌ 需手填或重搜 |

### 1.2 产品诉求

- **查价与锚点解耦**：Ignav 是参考价，**已购航班**才是 generate 的硬约束。
- **Trip.com 定位不变**：Deep Link 只做「预填搜索页」，**无法** deep link 到某一具体航班号；用户订完后仍需 App 内记录 `depart_at` / `arrive_at` 等。
- **诚实溯源**：手动录入应标 `source: manual`、`booking_status: booked_external`，与 Ignav 报价区分。

## 2. 现状与缺口

### 2.1 当前唯一写入路径

```
FlightIntelPanel.handleSearch()
  → POST /api/v1/flights/search
  → setFlightSearchResult({ ranked, purchase_url })
  → 用户点「确认选用」
  → confirmFlightQuote(quoteId, role)
  → flightLegFromQuote(quote, …)
  → travel_intel.flights[]
```

`confirmFlightQuote`（`usePlanStore.ts`）**强依赖** `last_flight_search.ranked` 中的 `FlightQuote`；没有 search session 则无法添加航段。

### 2.2 Trip.com 能提供什么

| 能力 | 有/无 | 说明 |
|------|-------|------|
| 预填搜索 URL | ✅ | `purchase.url` / `build_tripcom_flight_url(dcity, acity, ddate, …)` |
| 具体航班号 / 起降时刻 | ❌ | URL 仅到列表页，不回传用户最终选中的班次 |
| 订单详情 API | ❌ | 无 Trip.com 订单拉取；个人开发者不可行 |
| 联盟佣金链接 | ✅ | 已有 `TRIPCOM_*` affiliate 参数 |

因此：**Trip 信息 = 搜索入口 + 可选 `purchase_url` 存档**，不能自动变成 `ConfirmedFlightLeg`。

### 2.3 数据模型：已预留但未用

`ConfirmedFlightLeg`（`travelIntel.ts` / 方案 06）：

| 字段 | 手动添加用途 |
|------|----------------|
| `booking_status: 'selected' \| 'booked_external'` | 手填且已在 OTA 付款 → `booked_external` |
| `purchase_url?` | 粘贴 Trip.com 搜索页或订单相关链接 |
| `flight_numbers?` | 用户从行程单抄录 |
| `quote: FlightQuote` | **当前必填**；手填需**合成 quote** 或改 schema |

`FlightQuote.source` 现有值：`ignav` | `letsfg`。建议扩展 **`manual`**。

### 2.4 UI 缺口

`FlightIntelPanel` 仅有：

- 已确认航段列表（移除 + Trip 链接）
- Ignav 搜索表单
- 推荐结果卡片

**无**「手动添加」「我已订好」等等入口。方案 06 §5 表格曾写「支持添加航段」，P3 仍为 ⏳。

## 3. 设计原则

1. **双入口、同一落库**：Ignav 确认与手动添加都写入 `travel_intel.flights[]`，generate 不区分来源，但读 `quote.source` / `booking_status` 做展示与 warning。
2. **锚点字段优先**：generate 硬约束依赖 **起降时刻 + 机场**；价格、航司名为辅助展示。
3. **Trip 不阻塞手填**：始终保留 Trip.com CTA；手填表单与搜价表单并列，不隐藏。
4. **最小后端**：Phase 1 **纯前端**合成 `FlightQuote` + `ConfirmedFlightLeg` 即可；可选 Phase 2 增加校验 API。
5. **对齐现有 UX**：参考 `NodeCoordEditor` 的「搜索 / 手动输入」折叠模式，避免面板过长。

## 4. 推荐方案

### 4.1 交互结构（FlightIntelPanel）

```
┌─ 航班确认 ─────────────────────────────┐
│ 已确认航段（列表 · 移除 · Trip 链接）      │
├───────────────────────────────────────┤
│ [Tab 或折叠]                           │
│  · App 内查价（Ignav）    ← 现有        │
│  · 手动添加航段          ← 新增        │
├───────────────────────────────────────┤
│ Trip.com 查价与预订 →  （始终可见）       │
│ 说明：订好后在下方手动填写实际班次         │
└───────────────────────────────────────┘
```

**手动添加表单（必填 / 选填）**

| 字段 | 必填 | 控件 | 说明 |
|------|------|------|------|
| 航段类型 role | ✅ | 去程 / 回程 / 城际 | 与现有一致；非 intercity 覆盖同 role |
| 出发地 | ✅ | 文本（中文或 IATA） | 存 `origin_iata`；展示用 [07](./07-航班号与中文地名分析.md) 中文映射 |
| 目的地 | ✅ | 文本 | 同上 |
| 出发日期时间 | ✅ | `datetime-local` 或 日期+时间 | → `depart_at` ISO8601 |
| 到达日期时间 | ✅ | 同上 | → `arrive_at`；跨日合法 |
| 航司 | 建议 | 文本 | 如「春秋」「Singapore Airlines」 |
| 航班号 | 选填 | 文本，逗号分隔 | → `flight_numbers[]` |
| 经停 stops | 选填 | 数字，默认 0 | 可据 `flight_numbers` 数量推断 |
| 预订链接 | 选填 | URL | Trip 搜索页 / 航司确认页 |
| 已在 Trip/航司订好 | 选填 | checkbox | 勾选 → `booking_status: booked_external` |
| 参考价 | 选填 | 金额 + 币种 | 仅展示；默认 0 |

提交：**「添加航段」** → `addManualFlightLeg(input)` → toast「已添加航段」。

**预填**：打开手动表单时，用当前 `trip_request` / 搜索表单中的 origin、destination、date 预填，减少重复输入。

### 4.2 数据层：合成 FlightQuote

不新增后端 API 即可落地。新增工具函数：

```typescript
// frontend/src/types/travelIntel.ts

export interface ManualFlightLegInput {
  role: FlightLegRole;
  origin: string;           // 用户输入，解析后存 IATA
  destination: string;
  depart_at: string;        // ISO8601
  arrive_at: string;
  airline?: string;
  flight_numbers?: string[];
  stops?: number;
  purchase_url?: string;
  booked_external?: boolean;
  price_amount?: number;
  price_currency?: string;
}

export function flightLegFromManualInput(
  input: ManualFlightLegInput,
  opts: { sequence: number; defaultPurchaseUrl?: string },
): ConfirmedFlightLeg {
  const origin_iata = normalizeIata(input.origin);   // 大写；可选调 city alias 表
  const dest_iata = normalizeIata(input.destination);
  const duration_minutes = diffMinutes(input.depart_at, input.arrive_at);

  const quote: FlightQuote = {
    id: `manual-${crypto.randomUUID()}`,
    origin_iata,
    dest_iata,
    airline: input.airline?.trim() || '—',
    route_label: `${origin_iata}→${dest_iata}`,
    depart_time: input.depart_at,
    arrive_time: input.arrive_at,
    duration_minutes,
    stops: input.stops ?? 0,
    price_amount: input.price_amount ?? 0,
    price_currency: input.price_currency ?? 'CNY',
    source: 'manual',              // 扩展 FlightQuote.source 联合类型
    confidence: 'low',             // 用户自填，非 API 验证
    flight_numbers: input.flight_numbers,
  };

  return {
    id: crypto.randomUUID(),
    sequence: opts.sequence,
    role: input.role,
    origin_iata,
    dest_iata,
    depart_at: input.depart_at,
    arrive_at: input.arrive_at,
    airline: quote.airline,
    flight_numbers: input.flight_numbers,
    stops: quote.stops,
    duration_minutes,
    quote,
    quote_id: quote.id,
    purchase_url: input.purchase_url ?? opts.defaultPurchaseUrl,
    booking_status: input.booked_external ? 'booked_external' : 'selected',
    is_anchor: true,
  };
}
```

**Store**：


## 5. 方案对比

| 方案 | 描述 | 优点 | 缺点 | 建议 |
|------|------|------|------|------|
| **A. 纯前端手填** | 合成 quote，无新 API | 快、离线可用 | 无服务端校验 IATA/时刻 | **P1 采用** |
| **B. POST /flights/manual** | 后端校验 + normalize | 与 city_codes 统一 | 多一次请求 | P2 可选 |
| **C. LLM 解析粘贴** | 扩展 verify-from-text | 粘贴行程单/email | 不稳定、需 LLM | P3 增强 |
| **D. 仅 Trip 链接** | 只存 URL 不填时刻 | 极简 | generate 无硬约束 | ❌ 不够 |
| **E. 改 schema 去掉 quote** | quote 可选 | 模型更纯 | 破坏现有 generate 快照契约 | ❌ 改动大 |

## 6. 校验规则

### 6.1 前端（提交前）

| 规则 | 处理 |
|------|------|
| 出发/到达为空 | 禁用提交 |
| `arrive_at` ≤ `depart_at` | 错误提示（允许跨日：到达日可大于出发日） |
| 机场码无法识别 | 警告仍允许提交（存大写原文）；或阻断并提示 IATA |
| URL 格式 | 可选字段；非法 URL 警告 |
| 同 role 非 intercity | 覆盖旧段（与 `confirmFlightQuote` 一致） |

### 6.2 与 TripRequest 关系（软校验）

- 去程 `dest_iata` 宜与 `trip_request.destination` 一致 → warning 非 error（单国家多城例外）
- 日期落在 `date_start`～`date_end` 外 → warning

### 6.3 generate 行为

与方案 06 Q1 一致：**不阻塞 generate**。手动航段存在时：

- Prompt 注入 `flights[].depart_at / arrive_at / origin / dest`
- `meta.warnings` 若 `quote.source === 'manual'` 可加「部分航班为用户手动录入，请以其时刻为准」

## 10. 结论

| 问题 | 答案 |
|------|------|
| 是否需要手动添加？ | **需要** — Trip 只有搜索 CTA，无法回传具体班次 |
| 与 Ignav 关系？ | **并列入口**，同一 `flights[]` |
| 是否要做后端 API？ | **P1 不必**；校验 API 可 P2 |
| Trip 信息怎么用？ | `purchase_url` 存档 + 跳转查价 + 可选 URL 预填起终点日期 |
| 关键字段？ | `depart_at`、`arrive_at`、机场码；generate 锚点依赖它们 |
