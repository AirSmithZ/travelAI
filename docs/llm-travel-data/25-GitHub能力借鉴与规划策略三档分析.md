## 0. 结论摘要

| # | 结论 |
|---|------|
| 1 | **不 fork / 不依赖** 高星旅行 Agent 仓；只抽 **可验证能力模式** 进本仓确定性管道。 |
| 2 | 可借鉴优先级：**封闭 POI 池 > 代码/规则 Reviewer > API 并行先行 > HITL 打断 > 兴趣轻前置**；多角色 Crew / 搜网写行程 **明确不借**。 |
| 3 | UI 采纳 **规划策略三档**（A 机酒优先 / B 兴趣前置 / C 玩法优先），默认 **A**；与 [18](./18-机酒优先与迭代行程产品决策.md) 不冲突。 |
| 4 | 策略控件放在 **计划摘要卡旁或机酒流程入口前**（对话为主，[22](./22-对话编排与玩法印证UX调研.md)）；切换须 **可见后果 + 确认**，禁止静默改流水线。 |
| 5 | 工程上：策略 = `trip_request.planning_strategy` + 门禁差异；LLM 仍单次精排 / optimize / regenerate，**不上完整 Planner**。 |
| 6 | 越南案例（[P122](../问题日志.md)）：酒店搜区对、玩法围栏错 → 「酒店区域≠游玩落点」是**管道不对称**加重因素；主修仍是 GEO-13。 |

## 2. 可借鉴优点矩阵（相对本仓）

> 对照源见 [24 §2–§3](./24-GitHub旅行Agent调研与机酒玩法顺序讨论.md)。「借鉴」= 抽模式进现有服务，**不是**引入 LangGraph/CrewAI 依赖。

### 2.1 建议借鉴（按增益）

| 优先级 | 能力优点 | 代表源 | 对本仓的具体形态 | 为何值得 |
|--------|----------|--------|------------------|----------|
| **P0** | **封闭候选池，LLM 只排序/编排** | FloatTrip、TripStar | 扩展 `meta.poi_candidates` / Places / 已核验池 → generate 硬约束「只许从池选」；缺池项失败或降级提示 | 直接打「起名→geocode」主缺口；与 TravelPlanner「盲生成不过约束」一致 |
| **P0** | **围栏 / 坐标自带候选** | FloatTrip；本仓 GEO-11/12 | 行程 geocode **对称复用** `GeocodePlaceContext` / IATA fence（GEO-13） | 修胡志明错钉；不依赖换 Agent 框架 |
| **P1** | **代码规则 Reviewer（非再堆角色）** | FloatTrip G1–G7 | 生成后：跨城距离、出池、抵达日无早出、返程无晚入（已有部分 enforce）→ 统一 `validate_itinerary` 打回或 warning | llm-api：**可执行检查 > 多轮反思** |
| **P1** | **缺项失败（笔记/必去未校准则拒）** | TripStar 指定笔记模式 | C 档 / 贴链模式：骨架 POI 无法 geocode 进围栏 → **阻断精排**并对话说明 | 比「编一个像真的」更诚实 |
| **P1** | **API / 工具先行，LLM 只合成** | kbhujbal、HarimxChoi | 已有：Ignav / StayZone / Evidence / 天气并行注入；补齐玩法侧「池」即可接近架构 C/D | 与 AG-01 规则注入同向 |
| **P1** | **HITL 打断关键动作前** | nirbar `interrupt_before` | 机酒确认、策略切换、fork_plan、生成前门禁 — 已有精神；策略切换复用 Patch 确认范式 | ai-chat-ui：禁止静默改流水线 |
| **P2** | **轻量兴趣/必去清单（非整表草图）** | [24 §6.5](./24-GitHub旅行Agent调研与机酒玩法顺序讨论.md) | B 档：`must_see[]` / tags / 贴链 → **仅 bias 片区**，不跑第二轮完整 generate | 改善酒店片区，不推翻机酒主序 |
| **P2** | **节点引用可解释** | TripStar；讨论稿 evidence_refs | 卡片展示 `evidence_refs`（依赖围栏正确） | 可信度可见，接 [23](./23-玩法印证贴链MVP实施.md) |

### 2.2 明确不借鉴

| 不借项 | 代表 | 原因 |
|--------|------|------|
| 多角色 Crew「搜网写行程」 | CrewAI 官方例、AdritPal 7 Agent | 成本高、事实仍软；换壳不修错钉 |
| 完整 LangGraph Planner 中枢 | 多仓营销 | [18 §3](./18-机酒优先与迭代行程产品决策.md) ⏸；L1/L2 + 封闭池稳后再议 |
| 以 Amadeus 等为唯一机酒源 | shaheen / Harimx | 本仓 Phase 1 已定 Ignav + Trip 深链；Key/合规门槛高 |
| 「先完整草图玩法再机酒」两轮 LLM | 部分内容向产品 | [18 A1](./18-机酒优先与迭代行程产品决策.md) 已否；草图坐标更飘 |
| README 星数当选型标准 | nirbar 等 | 高星常是机酒 Tool Demo，玩法弱 |

### 2.3 一句话选型原则

```text
借「事实从哪来 + 谁检查约束」
不借「几个 Agent 角色 + 哪家编排框架」
```

## 3. 规划策略三档（产品契约）

### 3.1 三档定义

| 档 | ID | 用户心智 | 流水线 | 默认？ |
|----|-----|----------|--------|--------|
| **A 机酒优先** | `flight_hotel_first` | 「先定票和住哪，再排每天玩什么」 | 表单 → 机票确认 → 酒店/片区确认 → 玩法精排（封闭池） | **是** |
| **B 兴趣前置** | `interest_then_anchors` | 「我有必去/兴趣，帮我定片区再订机酒」 | 兴趣/必去/贴链 → 机酒（片区可 bias）→ 玩法精排 | 否 |
| **C 玩法优先** | `activity_first` | 「跟笔记/攻略走，或目的地未定」 | 骨架 POI/笔记校准 → 定城/机酒 → 精排；缺校准可阻断 | 否 |

```text
A  [OD/日期] → 飞确认 → 住确认 → POI池精排
B  [兴趣清单] → (片区 bias) → 飞确认 → 住确认 → POI池精排
C  [笔记/必去骨架] → POI校准 → 定城/机酒 → 精排
         └ 校准失败 → 对话阻断，不瞎生成
```

### 3.2 与「玩法倒推机酒」的边界

| 说法 | 是否采纳 |
|------|----------|
| 完整日程草图倒推航班 | ❌ |
| 兴趣/骨架 **轻微 bias 酒店片区**（B） | ✅ |
| 笔记骨架定城后再搜票（C） | ✅（场景门控） |
| 机票仍城市 OD | ✅（各档相同） |

酒店片区「倒推」在本仓已有 StayZone 路径（[12](./12-阶段B住宿区域倒推方案.md)）；三档只是 **何时、用什么输入去 bias**，不是另起一套 Agent。

### 3.3 门禁差异（逻辑）

| 门禁 | A | B | C |
|------|---|---|---|
| 生成前须锁定航班 | 是 | 是 | 目的地已定后：是；未定城：先定城 |
| 生成前须锁定酒店/片区 | 是（现 FLOW-01c） | 是 | 是（校准通过后） |
| 兴趣/必去 | 可选 | **建议有**（可空则降级 A 行为） | 骨架 **必填**（贴链或清单） |
| 骨架 POI 校准失败 | — | 软警告 | **硬阻断** |
| optimize / regenerate | 三档均保留；改机酒后 dirty banner | 同左 | 同左 |

## 4. UI / UX 形态（Skill 约束下）

### 4.1 控件放哪

对齐 [22](./22-对话编排与玩法印证UX调研.md)「对话为主 · 摘要只读」：

```text
对话区上方「计划摘要卡」
  ├─ 一行：规划策略  [ A机酒优先 | B兴趣前置 | C玩法优先 ]   ← segmented / radio group
  ├─ 只读：日期 · OD · 飞/住状态 · 印证条数
  └─ 未完成项点击 → 预填对话或打开机酒大面板（不在卡片上直接改字段）
```

- **不要**做成独立「策略向导」多步页（易与对话双轨）。  
- **不要**默认展开 C 的复杂说明；用 progressive disclosure：选中某档后一行短说明 +「适用场景」。

### 4.2 切换交互（ai-chat-ui）

| 规则 | 说明 |
|------|------|
| 有已确认机酒或已有行程时切换策略 | 弹出确认卡（类 PatchConfirm）：说明「门禁与下一步会变；行程不自动重跑」 |
| 确认文案 | 明确是否保留 `travel_intel`；默认 **保留机酒、标记玩法 dirty**（与 FLOW-02 一致） |
| 无锚点时切换 | 可即时切换，摘要卡更新策略标签即可 |
| Chat 改策略 | 允许自然语言 → FormPatch `set planning_strategy` → **仍须确认卡** |

### 4.3 ui-ux-pro-max 检查清单（本控件）

- [ ] 每档有可见 **label**（非仅靠颜色）  
- [ ] 选中态 + keyboard focus 可见  
- [ ] 切换后摘要卡即时反映；若需确认则 loading → success/cancel  
- [ ] 移动端：三档可横向 scroll 或改为等宽 radio，避免挤成图标谜语  
- [ ] 文案避免「Agent / Multi-agent」营销词；用用户语言（机酒优先 / 兴趣前置 / 跟笔记走）

### 4.4 各档 UI 增量（相对现状）

| 档 | 额外 UI |
|----|---------|
| A | 无；现有 Flight / Stay Panel + generate |
| B | 摘要卡下「必去/兴趣」芯片编辑（可对话追加）；StayZone 推荐展示 bias 原因一句 |
| C | 贴链/笔记模块前置（复用 [23](./23-玩法印证贴链MVP实施.md)）；校准结果列表（通过/失败 POI）；失败时禁用生成并给修复话术 |

## 5. 工程落点（分析级，非排期承诺）

| 层 | 建议 |
|----|------|
| Schema | `TripRequest.planning_strategy: 'flight_hotel_first' \| 'interest_then_anchors' \| 'activity_first'`，默认前者 |
| 门禁 | `generate` 按策略分支；C 增加 `skeleton_poi_ok` |
| Prompt | HARD 块注入策略说明 + 池约束；UGC/笔记进 `UNTRUSTED_UGC`（llm-api 隔离） |
| 管道 | 优先落地 GEO-13 + ACT-POOL；三档 UI 可先做 **A/B 可切、C 灰显或带「实验」** |
| Agent | 仍 **不** 上完整 Planner；逻辑角色保持 [18 §3](./18-机酒优先与迭代行程产品决策.md) |

## 6. 建议实施顺序（讨论稿）

```text
1. GEO-13 行程围栏对称          ← 与策略无关，先修错钉
2. ACT-POOL 封闭池 → LLM 只排   ← 最大可靠性增益
3. trip_request.planning_strategy + 摘要卡三档 UI（默认 A）
4. B：must_see / 兴趣 → StayZone bias
5. C：笔记骨架校准 + 硬阻断（可晚于 B）
6. 轻量 Reviewer 规则收口 + evidence_refs 展示
```

完整多 Agent / LangGraph：**继续 ⏸**。
