## 1. 业务目标

- 给出 **可比较的报价矩阵**（直飞 vs 中转、不同航司、不同出发时段）。
- 标注 **总价构成**（含税、行李、选座、燃油附加）。
- 支持 **弹性日期**（±1～3 天）与 **多机场**（如伦敦 LHR/LGW/STN）。

---

## 2. 推荐数据源（境外）

| 层级 | 来源 | 适用场景 | 备注 |
|------|------|----------|------|
| **GDS / 聚合** | Amadeus、Sabre、Travelport | 生产级搜索、部分可订 | Amadeus Self-Service **2026-07-17 停用** |
| **比价 / 元搜索** | Skyscanner、Kiwi、Google Flights | 广覆盖比价 | 无官方公开 API；常经 affiliate |
| **直连航司** | NDC、Duffel | 准确舱位与退改规则 | 接入成本高 |
| **兜底** | LLM + 联网搜索 | 仅趋势/参考价 | 必须标 `confidence: low` |

### 2.1 数据为何不透明（个人开发者）

| 误区 | 实际情况 |
|------|----------|
| 接个 API 就能全网比价 | 库存多在 GDS 或航司 NDC；无免费「最低价 API」 |
| Skyscanner / Google Flights 有公开 API | Skyscanner 仅商业 Partner；Google Flights **无官方 API** |
| Amadeus sandbox 长期可用 | Self-Service **2026-07-17 关停**（[PhocusWire](https://www.phocuswire.com/amadeus-shut-down-self-service-apis-portal-developers)） |
| LLM 联网能给出准确票价 | 多为幻觉或过时区间 |

## 3. 比价 Schema

```typescript
interface FlightQuote {
  id: string;
  origin_iata: string;
  dest_iata: string;
  depart_at: string;        // ISO8601 + 时区
  arrive_at: string;
  airline_codes: string[];
  stops: number;
  cabin: 'economy' | 'premium_economy' | 'business' | 'first';
  price: {
    amount: number;
    currency: string;
    includes_tax: boolean;
    baggage_included: string; // e.g. "1×23kg"
  };
  fare_rules_summary?: string;
  booking_deep_link?: string;
  source: string;
  fetched_at: string;
}
```

**LLM 职责**：

- 解析用户约束（红眼可否、最大中转时长、偏好航司）。
- 对 API 返回报价 **聚类**（同航线不同价 → 解释差异）。
- 写入行程：`category: 'airport'` 节点绑定 `flight_quote_id`，边 `transport_mode: 'flight'`。

**注意事项（境外）**：

- 护照有效期（通常 ≥6 个月）、过境签。
- 廉价航空机场偏远（STN、BGY）→ `tips` 加通勤成本。
- 跨时区 `day_index` 归属（凌晨抵达算 Day1 还是 Day0）。

## 4. 落地路线

| 阶段 | 方案 | 说明 |
|------|------|------|
| **Phase 1** | **Trip.com `showfarefirst` Deep Link** + LLM 选型 | 不展示票价；`cost_label: "请在 Trip.com 查询"`；详见 [实施方案](./01-航班信息-Trip.com实施方案.md) |


## 5. 豆包对话航班信息核验（2026-06-30）

**来源**：[豆包分享对话](https://www.doubao.com/thread/x3a3c2d6a18f587c3b87f587394a7fccd)  
**核验方式**：分享页嵌入内容 + GitHub API + 官方 Partner 文档

### 5.1 对话结论（不可作为选型依据）

豆包推荐 **RollingGo Flight MCP** 或 **letsfg**，称「全部为 GitHub 开源可直接用」。  
**整体叙事不可信**：链接错误、混淆商业 MCP 与开源、引用 SEO 软文。

### 5.2 逐条真伪核验

| 豆包说法 | 核实结果 | 结论 |
|----------|----------|------|
| `RollingGo-AI/rollinggo-mcp` | GitHub **404** | ❌ |
| RollingGo「开源、500+ 航司、订单闭环」 | 仅 [`rollinggo-hotel-mcp`](https://github.com/RollingGo-AI/rollinggo-hotel-mcp)；机票为商业 API | ⚠️ |
| `technicalerikchan/flight-mcp-server` | 存在，Amadeus MCP | ✅ |
| 「Amadeus = 官方数据源」 | GDS，非航司官方；SS 将停用 | ⚠️ |
| `maratsarbasov/flights-mcp` + Google Flights | 实际为 **Aviasales API** | ❌ |
| `travelcode-ai/mcp-travelcode` | 应为 `Travel-Code-Inc/mcp-travelcode` | ⚠️ |
| `letsfg/letsfg` | [`LetsFG/LetsFG`](https://github.com/LetsFG/LetsFG) ~1.2k ⭐ | ✅ 相对最可信 |
| `aweirddev/flights` | Google Flights 爬虫 | ✅ 真，⚠️ 合规风险 |
| `flight-spy/flight-spy` | **404**；真项目 `jeancsil/flight-spy` | ❌ |
| FlightSpy + Skyscanner API | SEO 软文；Skyscanner 仅 [Partner](https://www.partners.skyscanner.net/contact/travel-api) | ❌ |
| `openclaw-dev/flyclaw` | **404**；近似 `AI4MSE/FlyClaw` | ❌ |
| Spring AI `flight-assistant` | 仓库无该目录 | ❌ |

**统计**：11 项中明确错误 5，夸大 5，相对可信 1（letsfg）。

### 5.3 值得实测的开源项

| 项目 | Stars | 用途 | 风险 |
|------|-------|------|------|
| [LetsFG/LetsFG](https://github.com/LetsFG/LetsFG) | ~1.2k | Agent 航班搜索 | 价差不保证 |

## 6. 快速验证专项（Spike）— 独立项目方案

> **思路**：不在 travel 仓库里直接接 API。另建 **`flight-spike`**（或任意临时目录），用固定测试航线跑通 3～4 种数据源，产出对比报告后再决定接入 travel 的 Provider 与 Schema。  
> **目标**：回答「我们能不能拿到结构化航班报价？延迟/稳定性/合规如何？」—— 不是做 UI，也不是做完整 Agent。

### 6.1 为什么单独开项目

| 在 travel 里直接试 | 独立 Spike 项目 |
|-------------------|-----------------|
| 与 Itinerary / 前端耦合，改一处动全身 | 只验证「搜航班 → 出 JSON」 |
| 失败难归因（LLM？Geocode？航班源？） | 失败范围清晰 |
| 难以保留多源对比快照 | `output/` 按日期存原始响应，便于复盘 |
| 验证中途可抛弃，不污染主仓库 Git 历史 | Spike 仓库可归档或删除 |

**建议耗时**：专注 1～2 天可完成 Tier 0～3 对比；第 3 天写 `REPORT.md` 做 Go/No-Go。

### 6.2 Spike 仓库结构（最小）

```
flight-spike/
├── README.md                 # 怎么跑、测哪几条线
├── requirements.txt          # flights, duffelbag, httpx …
├── fixtures/
│   └── routes.json           # 标准测试航线（见 §6.3）
├── scripts/
│   ├── tier0_deeplink.py     # 只生成 URL，0 依赖
│   ├── tier1_letsfg.sh       # CLI 包装
│   ├── tier2_google_flights.py  # AWeirdDev/flights
│   └── tier3_duffel.py       # 官方 sandbox API
├── output/                   # 每次运行落盘 JSON（gitignore）
│   └── 2026-07-01/
└── REPORT.md                 # 对比结论 + 接入建议
```

**环境**：Python 3.11+、可选 Node（若试 MCP）。**不要**把 API Key 提交进 Git；用 `.env` + `.env.example`。

### 6.4 分 Tier 验证（由快到慢）

按顺序做；**任一 Tier 已满足你的最低需求，可停止上探**。

#### Tier 0 — Deep Link 基线（≈30 分钟）

**验证什么**：零 API 能否「帮用户去搜」；作为 Fallback 永远可用。

```python
# scripts/tier0_deeplink.py
from urllib.parse import quote
def google_flights_url(origin, dest, date):
    q = quote(f"Flights {origin} to {dest} on {date}")
    return f"https://www.google.com/travel/flights?q={q}"
```

**通过标准**：3 条航线均能生成可点击 URL；人工打开与 OTA 页面对得上城市/日期。

**不验证**：具体票价、舱位、行李。

---

#### Tier 1 — LetsFG CLI（≈2～4 小时）

**验证什么**：无 API Key、本地连接器能否返回**结构化**报价（豆包清单里相对最可信的一项）。

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install "letsfg[cli]"

# 单条（首次可能较慢，建议 timeout ≥180s）
time letsfg search PVG SIN 2026-10-16

# 往返
letsfg search HKG NRT 2026-11-01 --return 2026-11-08
```

**通过标准**：

| 指标 | 建议阈值 |
|------|----------|
| 成功率 | 3 条航线 ≥2 条有结果 |
| 延迟 | 记录 P50/P95；若 P95 >120s 需包装异步任务 | **实测 PVG→SIN ≈158s（fast 模式）**，必须异步 |
| 结构 | 能解析出航司、起降时刻、总价（币种） |
| 稳定 | 同一航线间隔 1h 连跑 3 次，价格偏差 <15% 或有合理解释 |

**已知风险**：本地跑 180+ 连接器，**首查可能 2～5 分钟**；部分航司连接器会失败；合规取决于各航司 ToS。**实测（2026-07-01）**：预订链接需 [LetsFG 付费解锁](https://letsfg.co)；详见 [验证报告 §3.2](./01-航班信息-Spike验证报告.md#32-tier-1--letsfg-cli-️)。

**包装示例**（Spike 里先写脚本，travel 里再变 FastAPI）：

```bash
letsfg search PVG SIN 2026-10-16 --json 2>/dev/null | tee output/$(date +%F)/letsfg-pvg-sin.json
```

（若 CLI 无 `--json`，stdout 解析或查 LetsFG Python SDK。）

---

#### Tier 2 — Google Flights 爬虫（≈2～4 小时）

**验证什么**：[`AWeirdDev/flights`](https://github.com/AWeirdDev/flights) 能否作为**参考价**补充源。

```bash
pip install fast-flights   # PyPI；v3 API 见验证报告 §7
```

```python
# scripts/tier2_google_flights.py（fast-flights v3）
from fast_flights import FlightQuery, Passengers, create_query, get_flights

q = create_query(
    flights=[FlightQuery(date="2026-10-16", from_airport="PVG", to_airport="SIN")],
    trip="one-way",
    passengers=Passengers(adults=1),
    seat="economy",
    currency="USD",
)
result = get_flights(q)
```

**通过标准**：能返回多条 offer；与 Tier 1 或人工 Google Flights 页面**量级一致**（不要求分毫不差）。

**失败即记录**：403/空结果/结构变更 — 标记为「不可作生产依赖」，仅保留 Tier 0/1。

---

#### Tier 3 — Duffel Sandbox API（≈0.5～1 天）

**验证什么**：**唯一适合写进产品的正式 REST 契约**（搜索 → Offer → 可选下单测试）。

1. 注册 [Duffel Dashboard](https://app.duffel.com) → Developer test mode  
2. 创建 `duffel_test_*` Token（[Test mode 文档](https://duffel.com/docs/api/overview/test-mode)）  
3. 跑通 Offer Request：

```bash
curl --compressed https://api.duffel.com/air/offer_requests \
  -H "Authorization: Bearer $DUFFEL_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Duffel-Version: v2" \
  -d '{
    "data": {
      "slices": [{"origin": "LHR", "destination": "JFK", "departure_date": "2026-07-15"}],
      "passengers": [{"type": "adult"}],
      "cabin_class": "economy"
    }
  }'
```

Python 可用 [duffelbag](https://github.com/nickovs/duffelbag) 或官方 SDK；Postman 集合见 [Duffel Quick Start](https://www.postman.com/duffelhq/duffel/)。

**通过标准**：

| 指标 | 说明 |
|------|------|
| 响应 Schema | 能映射到 §3 `FlightQuote` |
| 延迟 | API 通常 <10s；适合在线请求 |
| 测试数据 | Sandbox 价/时刻**不真实**（Duffel Airways）；验证的是**集成能力**，不是亚太实价 |
| 生产路径 | 需 Duffel 生产 Token + 商务条款；亚太覆盖需单独评估 |

**可选**：用 [hackathon-starter-kit](https://github.com/duffelhq/hackathon-starter-kit) 半天内跑通 search → book → cancel 全链路。

### 6.6 验证通过后再接入 travel 项目

Spike 与主项目之间只保留**薄适配层**，避免把 Spike 脚本 copy-paste 进 `backend/`：

```
backend/app/services/flight/
├── __init__.py
├── provider.py          # Protocol: search(request) -> list[FlightQuote]
├── deeplink.py          # Tier 0（永远保留）
├── letsfg_provider.py   # Tier 1（若 Go B）
├── duffel_provider.py   # Tier 3（若 Go C）
└── normalize.py         # 各源 → §3 FlightQuote
```

**配置**（`.env`）：

```bash
FLIGHT_PROVIDER=deeplink   # deeplink | letsfg | duffel
DUFFEL_TOKEN=              # 仅 duffel
FLIGHT_SEARCH_TIMEOUT_SEC=120
```

**接入步骤**（顺序）：

1. 把 Spike 的 `normalize.py` + 通过 Tier 的 provider 迁入 `backend/app/services/flight/`  
2. 新增 `POST /api/v1/flights/search`（仅返回 `FlightQuote[]`，**不**写入 Itinerary）  
3. 前端 / LLM Tool Calling 先调该 API，人工确认后再 Patch 进 `airport` 节点  
4. Itinerary 仍用 §3 字段；`meta.provenance[]` 记录 `source` + `fetched_at`

**原则**：Spike 仓库可删；travel 里只留 Provider 接口 + 一种默认实现 + 文档链接回本 §6。
