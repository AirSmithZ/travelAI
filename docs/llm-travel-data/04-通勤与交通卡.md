## 1. 三层通勤模型

| 层级 | 范围 | 数据需求 | 现有 Schema |
|------|------|----------|-------------|
| **L1 跨城** | 国际航班、欧铁、长途巴士 | 航班 + Rail API | `transport_mode: 'flight'` |
| **L2 城内** | 地铁、公交、有轨、轮渡 | Directions、GTFS | `subway` / `bus` / `ferry` |
| **L3 最后一公里** | 步行、打车、共享单车 | OSRM / Google Directions | `walk` / `taxi` |

## 2. 路线与票价 API

| 地区 | 路线规划 | 实时数据 |
|------|----------|----------|
| **全球兜底** | Google Directions、Mapbox、OSRM | 精度因城市而异 |
| **新加坡** | LTA **DataMall**（免费 Account Key） | 公交/地铁到站 |
| **日本** | Navitime、JR 时刻表、GTFS（部分） | 无统一 IC 卡 API |
| **欧洲** | DB、SNCF、Omio | GTFS 多国 |
| **英美** | TfL API、MBTA V3 | 实时到站 |

**原则**：**LLM 不应单独估算** `duration_minutes`；优先 API，失败时在 `meta.warnings` 标注「时间为估算」。

## 3. 公共交通办卡 / 票务（境外知识库）

IC 卡/通票 **无全球统一 API**，宜维护 **目的地 YAML/JSON 知识库**（定期人工审核）：

| 目的地 | 卡/票类型 | 是否必须办卡 | 典型费用 | 备注 |
|--------|-----------|--------------|----------|------|
| 新加坡 | EZ-Link / SimplyGo / **STP** | 否（可 tap 银行卡） | STP 1 日 S$17 起 | 机场/地铁站 |
| 日本 | Suica / PASMO / **Tourist PASMO** | 强烈建议 | 押金因卡种而异 | 2026 Tourist PASMO 机场专售 |
| 伦敦 | Oyster / Contactless cap | 否 | 按 zone | 儿童优惠 |
| 香港 | 八达通 | 建议 | HK$50 含押金 | MTR |
| 首尔 | T-money | 建议 | ₩2500 卡费 | 便利店充值 |
| 欧洲多国 | Eurail / 各国通票 | 视行程 | — | 与市内 IC 分离 |

### 5.1 Phase 2a 实现要点（TRN-01）

**API**：`POST /api/v1/commute/lookup`

```json
{
  "from_point": { "lat": 1.28, "lng": 103.85, "name": "滨海湾" },
  "to_point": { "lat": 1.30, "lng": 103.83, "name": "乌节路" },
  "free_text": "用户原始行程描述…",
  "notes": "",
  "use_directions": true
}
```

**候选来源优先级（展示可多选）**

1. **`user_hint`**：从 `trip_request.free_text` / `notes` 抽取「A→B + 轮渡/山路/缆车/地铁… + N分钟」；Directions 常失败的海路/山路标为推荐  
2. **`directions`**：SerpApi，按直线距离选 1–2 个 `travel_mode`（控费）  
3. **`estimate`**：haversine 直线估算（无 Key / 双失败时）

**边字段**：`route_source?: 'directions' | 'user_hint' | 'estimate'`；写回 `transport_mode` / `duration_minutes` / `distance_meters` / `label`。

**UI**：连线侧栏 `EdgeEditor` →「查询通勤」→ 候选列表一键应用。

**未做（刻意）**：generate 全量自动 Directions（成本/延迟）；交通卡 YAML KB。

### 5.2 Phase 2b 可疑边自动补算（TRN-02）

**触发**：`geocode` 完成之后（同步 generate / 异步 `geocode-nodes`）。

**可疑判定**（已 `route_source∈{directions,user_hint}` 则跳过）：

- `walk` 且直线 ≥ `COMMUTE_SUSPICIOUS_WALK_M`（默认 900m）
- 直线 ≥ `COMMUTE_SUSPICIOUS_LONG_M`（默认 3km）
- 时长为默认值 0/15/20/25 且直线 ≥ 1.5km
- 机场/酒店相关边仍标 walk 且 ≥ 800m

**控费**：按嫌疑分排序，最多 `COMMUTE_AUTO_MAX_EDGES`（默认 8）；Directions 结果进程内 TTL 缓存（`COMMUTE_CACHE_TTL_SEC`，默认 7 天）。

**写回**：推荐候选 → 边字段 + `meta.commute_auto_enriched` + warning「已自动核实 N 段可疑通勤」。

**配置**（`.env`）：`COMMUTE_AUTO_ENRICH` / `COMMUTE_AUTO_USE_DIRECTIONS` / `COMMUTE_AUTO_MAX_EDGES` / `COMMUTE_CACHE_TTL_SEC` / `COMMUTE_SUSPICIOUS_*_M`。

**主键**：`commute/enrich.py` · `commute/cache.py` · `itinerary_llm._after_geocode_enrich` · `geocode-nodes` 透传 `free_text`/`notes`。

### 5.3 Phase 2b′ 核实后时刻接龙（TRN-02b）

**问题**：边 `duration_minutes` 更新后，节点 `start_time`/`end_time` 仍按旧 gap 排布，纸面可行、落地撞车。

**做法**

1. 后端：`enrich` 之后调用 `realign_schedules_after_commute` → 复用 `align_day_schedules`（gap=`max(15, edge.duration_minutes)`；`meta.flight_bindings` + 过夜酒店锚定不变）
2. 前端：EdgeEditor 应用通勤候选 / 改耗时后，`cascadeDayScheduleFromEdges` 重排当日弹性节点

**Warning**：自动补算改过边时追加「已按通勤边时长重排当日节点时刻」。

**主键**：`intel_anchor_enforce.realign_schedules_after_commute` · `scheduleCascade.ts` · `test_commute_schedule_realign.py`

## 6. 豆包对话 Trip.com 火车数据核验

**来源**：同 [Trip.com MCP 对话](https://www.doubao.com/thread/x2b906885bbdb81ce91d412c004cdc7e9)（总览见 [02-酒店信息.md §5](./02-酒店信息.md#5-豆包对话-tripcom-数据源核验2026-06-30)）

豆包称 Apify Scraper 支持 **跨国/国内火车票线路、车次详情**。

| 说法 | 核验 | 结论 |
|------|------|------|
| Actor 含 Trains 能力 | README：route search + per-train detail | ✅ |
| 可支撑欧铁/跨境规划 | 覆盖取决于 Trip.com 站点与爬虫稳定性，**未验证具体国家** | ⚠️ |
| 替代 Omio/国铁 GTFS | 爬虫非官方时刻表；境内火车见附录境内占位 | ❌ 不宜作 L1 核心 |

**本项目建议**：境外 L1 跨城仍以 **航班 deep link** 为主（[01-航班信息.md](./01-航班信息.md)）；火车片段若出现，Phase 2 可用 Apify **参考**，`meta.warnings` 注明非官方时刻。
