## 0. 一句话结论

| 判断 | 结论 |
|------|------|
| 对话与表单谁主谁辅？ | **对话编排为主，表单（含机酒大面板）为辅** |

**对用户提案的回应**：在对话框某处展示「已完善的表单/机酒摘要、只支持查看，修改通过对话」——**比现状更好**，应作为 UX 主轴采纳。它直接解决「不知道完成了哪些 / 对话与表单双轨打架」，且不破坏「LLM 不静默改数据」的安全边界（写仍需确认或对话意图）。长任务必须在对话内可见运行步骤（§3b），不能只靠顶栏 StatusBar。

## 2. 产品决策：对话为主 · 摘要只读 · 表单为辅

### 2.1 原则（已拍板意向）

1. **单一编排面 = 对话**  
   用户主要用自然语言推进：补需求 → 搜/确认机酒 → 看印证 → 生成玩法。
2. **计划摘要卡 = 只读仪表**（钉在对话区上方或可展开）  
   - 展示：`trip_request` 关键字段、航班确认状态、住宿片区/酒店状态、玩法印证条数、是否已有行程。  
   - **交互：仅查看 / 展开折叠**；卡片上 **不提供** 直接改字段的输入框（避免与对话双写）。  
   - 未完成项用视觉标记（如「缺航班」「缺日期」），点击未完成项 → **预填一句对话建议**或打开对应大面板（机酒），而不是打开可编辑表单页。
3. **修改路径**  
   - 轻字段（目的地、天数、偏好）：用户对话说明 → FormPatch **批量确认一次**（或低风险自动写入 + Undo）。  
   - 机酒：对话短卡 / 摘要入口 → **Flight / Stay 大面板**（人确认列表项）→ 写回 `travel_intel`。  
   - 行程节点：生成后仍可用图选 + 侧栏精修，或 supplement 对话；与「需求摘要卡」分离。
4. **生成意图**  
   识别「生成 / 排玩法」→ 对话内 **ReadinessChecklist**（已有/缺少）→ 齐备才 `generate`；缺项 CTA 指向补对话或打开机酒面板。

### 2.2 为什么比「表单内嵌可编辑」更好

| 方案 | 评价 |
|------|------|
| 摘要卡只读 + 对话改 | **采纳**：进度可见、单一写入路径、符合 ai-chat-ui「确认后写入」 |
| 摘要卡内直接改字段 | 易与 pending patch 冲突；用户不知以谁为准 |
| 整表永久嵌在对话里可编辑 | 对话变仪表盘；机酒密度撑爆气泡 |
| 维持现状双轨（chat strip ↔ form） | 继续混乱 |

### 2.3 摘要卡建议字段（只读）

| 区块 | 完成判据（示例） | 未完成时对话提示方向 |
|------|------------------|----------------------|
| 目的地 / 出发 | `destination`（及可选 `departure`）非空 | 「目的地还没定」 |
| 日程 | `day_count` 或 `date_start`+`date_end` | 「还缺天数或起止日期」 |
| 偏好 / 预算 | tags 或 budget / `hotel_budget_per_night`（可选） | 软提示 |
| 航班 | `travel_intel.flights.length > 0` | 「请先确认航班」→ 打开机票面板 |
| 住宿 | 已确认 zone 或 hotel（软门槛，与 generate 警告对齐） | 「可确认住宿片区」 |
| 玩法印证 | Evidence 条数 / 核验 POI 数（后续） | 「印证较弱，仍可生成」 |
| 行程图 | `itinerary.days.length > 0` | 「可以生成玩法了」/「已生成」 |

摘要数据一律读 store 真相源（`trip_request` + `travel_intel` + `itinerary.meta`），不另维护第二份表单 state。

### 2.4 与「机酒大面板 + 搜索缓存」的关系

- 摘要卡只显示「已确认 2 段航班 · PVG→SIN …」级别摘要，**不渲染报价列表**。  
- 报价 / 片区地图仍在大面板；同 `request_key`（及 lodging key）前端缓存 + TTL +「刷新」（实施波再做）。  
- 与文档 18「人确认列表、不自动锁 Top1」一致。

## 3b. 运行过程与「思考」可见性（高优先级体验）

> 用户明确要求：进程跑的时候要在**对话框里**看到运行过程与思考过程，否则会以为没在跑或卡住。  
> **结论：必须做；且应落在消息时间线内，不能只靠顶栏一条 status。**

### 3b.1 现状缺口

| 能力 | 现状 | 问题 |
|------|------|------|
| Chat 解析 | `streamingHint` 进气泡；无内容时 **30s** 才出「仍在解析」 | 前 30s 几乎空白，最像「卡住」 |
| 行程生成 | `llmPreview` 可进气泡；`ChatStatusBar` 另有文案 | Status 与气泡分裂；**Evidence 拉取无步骤事件**，长等待空白 |
| Geocode | StatusBar 显示 `done/total` | **不在对话气泡里**，用户盯消息区会漏看 |
| 航班搜索 | Toast + 切面板 | 对话区无「正在搜票…」叙事 |
| 模型思维链 | 未接 `reasoning_content` 一类字段 | 用户说的「思考」目前**没有**产品面 |

### 3b.2 两层信息：别混为一谈

| 层 | 是什么 | 是否默认展示 | 说明 |
|----|--------|--------------|------|
| **A. 流水线步骤（必做）** | 解析中 → 校验 → 搜印证 → 写行程 → 补坐标 | **是**，主展示 | 确定性、可本地生成文案，不依赖模型「内心独白」 |
| **B. 模型思考/推理（可选）** | Provider 的 reasoning / 中间草稿 | **折叠默认收起** | 有则展示；无则不要用假「思考中：……」糊弄。长 CoT 有噪声与注入面，不宜整段常驻 |

用户体感上的「在思考」，用 **A 层步骤 + 流式预览 + 已用时** 即可覆盖 90%；B 层是增强，不是前提。

### 3b.3 推荐交互：对话内「进行中」气泡（Activity）

```text
用户: 帮我生成玩法
助手（进行中气泡，钉在列表底，脉冲光标）:
  ✓ 已确认航班与目的地
  … 正在检索玩法参考（小红书等）   12s
  ○ 生成日程
  ○ 补全地图坐标
  ─ 可选折叠「详情」：SSE 原文预览 / 条数
```

规则：

1. **发送后 <100ms** 插入进行中气泡（立刻有反馈），不要等首 token。  
2. 步骤由前端根据 SSE `progress.step` + 本地阶段推进；文案固定中文，不让 LLM 现场编进度。  
3. **已用时**每秒刷新（`12s`），证明心跳还在（配合已有 SSE ping）。  
4. 完成后：进行中气泡 **收束** 为一条正式助手消息（结果摘要 + 可折叠「本次过程 · 用时 78s」），写入 `chat_messages`，可回看。  
5. 失败：同气泡变错误态 + 可重试，不静默消失。  
6. Composer `aria-busy` + 禁用发送（已有 busy）保持；**进度以消息区为准**，StatusBar 可降级为次要或只保留 API/模式。

### 3b.4 进度事件（多数已落地 · 2026-08-08）

> **纠正**（见 [组合评估 §四](../doc21-22-玩法印证组合评估.md)）：缺口主要在「前端是否渲染」，不是「后端有没有 progress」。`evidence` 步骤后端早已 yield；Wave A 已用 Activity 气泡消费。

| step | 状态 | 说明 |
|------|------|------|
| `evidence` / `llm` / `geocode` | ✅ | generate SSE + `ChatActivityBubble` |
| 航班搜 Activity | ✅ | `executeChatToolCalls` |
| ChatStatusBar `evidence` 分支 | 🔲 | 顶栏仍可能空白；P3 补强 |
| `ack` 独立事件 | 可选 | 前端本地立刻插 Activity 已等同 ack |

**勿再排期「后端补 evidence progress」**（会修错层）。`UX-EVD-01` / StatusBar evidence ✅；剩余 `UX-CHAT-07`。

### 3b.5 「思考过程」怎么做才干净

| 做法 | 建议 |
|------|------|
| 假打字「正在思考深度计划…」循环文案 | ❌ 不信任感 |
| 直接把模型 CoT 全量刷进主气泡 | ❌ 冗长；可能含指令干扰 |
| 流水线步骤 + 流式 **结果预览**（行程 JSON/摘要片段） | ✅ 主路径 |
| 若 API 提供 reasoning：放进「过程」折叠区，上限截断 | ✅ 可选 |
| 解析阶段：步骤「理解需求 → 提取字段 → 待你确认」 | ✅ 比空等强 |

### 3b.6 与只读摘要卡、生成 checklist 的关系

- 摘要卡：静态完成度（做完了什么）。  
- Activity 气泡：动态（正在做什么）。  
- Checklist：点「生成」时的门禁结果（缺什么）。  
三者都在对话区，但职责不重叠。

## 4. 目标用户路径（应然）

```text
打开计划（对话为主，预览可按 UX-14 折叠）

       · 齐备 → generate → 行程图展开
  → 改需求：继续对话（摘要只读刷新）；改机酒：面板 + dirty banner
```

## 6. 风险与优化方案（实施约束）

> 对应「这样改会有什么问题」的缓解清单；实施时按表执行，勿只做摘要卡不做缓解。

### 6.1 产品 / 交互

| 风险 | 优化方案 |
|------|----------|
| 只读后改字段变绕 | ① 未完成项点击 → **预填 composer**（如「把行程改成 5 天」）一键发送或可改再发；② 摘要「已完成」旁提供 **「用对话修改」** 芯片（同样预填）；③ **不**在卡片上放 input。属 `UX-CHAT-01`。 |
| 批量确认 / 自动写入误改 | ① 仅白名单低风险字段自动写（如 `preference_tags` append、`free_text` 补全）；② `destination` / `fork_plan` / 日期大改 **必确认**；③ 写入后 **5～10s Undo 条**（撤销上一批 patch）。属 `UX-CHAT-03`。 |
| 跳大面板像踢出对话 | ① 机酒用 **右侧/底层抽屉** 而非整页替换左栏（首选），或全高面板但保留顶栏「返回对话」固定；② 对话留短卡「正在选航班 · 已确认 0/2」；③ 确认后 **自动回对话** + `UX-CHAT-09` CTA。 |
| Activity 假热闹 | ① 步骤文案只映射真实 `progress.step`；② 禁止轮播假 CoT；③ 超过 N 秒无事件仍只加计时，不编造新步骤；④ 可选折叠「详情」才显示 preview 片段。属 `UX-CHAT-05/07`。 |

### 6.2 技术 / 状态

| 风险 | 优化方案 |
|------|----------|
| 摘要与 store 双源漂移 | 摘要卡 **纯派生** `trip_request` + `travel_intel` + `itinerary`；禁止本地 editable draft。单测：改 store → 卡 UI 同步。 |
| 进行中气泡刷新丢失 | ① 进行中用 **ephemeral UI state**（`activitySession`）；② **完成/失败才**写入一条 `chat_messages`（含 steps 摘要 + latency）；③ `beforeunload` / 切计划：进行中标「已中断」或丢弃 ephemeral，不留半截永久消息。 |
| map 折叠左栏 | **`UX-CHAT-08`**：`leftPanelMode ∈ {flight,stay}` 或 `activitySession.active` 时，`selectLeftPanelCollapsed` 强制 false；地图与对话分屏（预览仍可看 map）。住宿 recommend **不再**为看几何而牺牲对话。 |
| SSE 扩字段兼容 | 未知 `event` / `step` 客户端 ignore；旧前端不崩。先发前端容错，再发后端新 step。属 `UX-CHAT-06`。 |
| 机酒齐了却不生成 | **`UX-CHAT-09`**：`confirmFlightQuote` / 确认片区后 `addChatMessage` 系统或助手短卡：「航班已确认。可以说『生成玩法』或点此生成」；按钮调 readiness → generate。不自动 regenerate（遵守 18）。 |

## 8. 验收想象（实施后）

1. 用户不打开「行程编辑」也能从摘要卡看出：目的地✅、航班❌、行程❌。  
2. 说「生成玩法」时，助手用清单回复缺航班，而非静默失败或只 toast。  
3. 摘要卡无输入框；改天数必须说话（或确认卡），store 与摘要一致。  
4. 机酒仍在大面板完成确认；对话仅摘要 + 入口。  
5. 玩法印证状态可见；技术侧仍走 EvidencePack，不依赖 Agent-Reach 运行时。  
6. 任意长耗时操作在对话时间线内有进行中气泡与步骤/计时；完成后过程可折叠回看。  
7. 打开地图/住宿推荐时对话区仍可用；确认航班后对话出现「可生成」CTA。  
8. 误确认支持 Undo；Activity 无假步骤文案。  
9. **UX-CHAT-10**：行程未生成时「计划摘要」卡内右栏为「下一步」指引（文案 + 一键跳转机票/酒店面板；窄屏上下叠），避免用户以为对话结束后无操作。  
10. **UX-CHAT-11**：对话态输入框下不再挂航班/住宿/印证/预览 strip；点摘要行开对应面板或地图；生成后底栏仍可「节点编辑」。
