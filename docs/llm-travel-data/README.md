## 1. 结论摘要

| 维度 | 现状 | 现实可达目标（修订） |
|------|------|----------------------|
| **Skill 覆盖** | 无专用「旅行规划 / 旅行数据」Skill | 建议新建 `travel-data-intelligence` Skill |
| **数据获取** | LLM 纯生成 POI + 地理编码；**无实时航班/酒店 API** | **分三层**：A 行程编排 ✅ / B 结构化参考信息 ⚠️ / C 实时可订报价 ❌ |
| **比价格** | `cost` / `cost_label` 由模型估算 | Phase 1 **不比价**，仅 deep link；Phase 2+ 接 Duffel 等 |
| **准确性** | 坐标走 `resolve_place`；费用靠模型「猜」 | 事实类走 API/官方页；无 API 时标 `confidence: low` |
| **行业透明度** | — | 机票/酒店对个人开发者**不透明**（见 [01-航班信息.md](./01-航班信息.md)） |

**产品定位**：

> 先做 **智能行程规划**（POI、动线、时间、注意事项），**不做订票平台**。  
> 机票/酒店 Phase 1 用「帮你搜」（预填链接），Phase 2+ 才考虑「帮你比价/参考价」。

**核心原则（境外）**：

1. **LLM 不编造可验证数字** — 必须带 `source`、`fetched_at`、`confidence`。
2. **比价需要可比维度**（舱等、取消政策、含税总价、入住人数/晚数）。
3. **游玩项目按品类拆 Schema**（见 [03-游玩项目.md](./03-游玩项目.md)）。
4. **通勤分三层**（见 [04-通勤与交通卡.md](./04-通勤与交通卡.md)）。
5. **细节清单化**（见 [05-行前细节清单.md](./05-行前细节清单.md)）。

### 1.1 现实落地边界（三层能力）

| 层级 | 能力 | 本项目现状 | Phase 1 可达 | 需商业合作 |
|------|------|------------|--------------|------------|
| **A** | 行程 POI / 动线 / 时间 / tips | ✅ LLM + Geocode + Mock | ✅ | 否 |
| **B** | 开放时间、预约、交通卡、签证规则 | 部分靠 LLM 猜 | ⚠️ 知识库 + Places + Directions | 部分 |
| **C** | 机票/酒店**实时报价与比价** | ❌ 无 | ❌ | **是** |

**Mock 中 `cost: { amount, currency }` 在未接 API 前应视为 UI 占位，不可称为智能比价。**

## 2. 实施路线图（修订 · 可执行）

| 阶段 | 航班 | 酒店 | 其他 | 产出 |
|------|------|------|------|------|
| **Phase 1**（1～2 周） | deep link，不比价 | Booking/Agoda 搜索链接 | 行程编排不变 | 诚实型 MVP |
| **Phase 2**（1～2 月） | LetsFG / AWeirdDev/flights 实测 | Google Places | Directions、**和风天气**、Tavily、Klook/Viator | 半结构化 Intel |
| **Phase 3**（3～6 月+） | Duffel / Amadeus Enterprise | Expedia EPS / Hotelbeds | 交通卡/签证 YAML | 可展示参考价 |
| **Phase 4** | 弹性日期、延误重排 | 多 OTA 归一（若合规） | 境内旅行专项 | 智能优化 |

详见各专题文档中的「落地路线」小节。

## 3. 风险与合规

- **API 条款**：OTA 报价需 affiliate 披露；禁止缓存禁止字段。
- **Amadeus Self-Service 停用**（2026-07-17）：评估 Enterprise 或 Duffel。
- **个人数据**：护照号不进 prompt；日志脱敏。
- **价格误导**：强制展示 `fetched_at` 与免责声明。
