# 总览模式路线图 · 视觉与信息架构分析

> 更新：2026-06-30  
> 依据：`design-taste-frontend`、`frontend-design` skill + 现有实现代码审阅  
> 范围：仅分析「路线图 · 总览」视图（`OverviewGraphView`），不含地图 Tab

---

## 1. 背景与目标

总览模式要让用户在**一张图里看清整趟行程**：哪天、在哪个区域、按什么顺序、怎么移动。  
单日模式用 React Flow 时间轴泳道已经能表达「一条路」；总览要表达的是**矩阵关系**（天 × 区域 × 路线），信息密度天然更高。

**用户核心诉求（按优先级）**

| 优先级 | 诉求 | 当前满足度 |
|--------|------|------------|
| P0 | 快速扫一眼：几天、每天去哪几个区 | 中 |
| P0 | 看出每天的游玩顺序 | 低 |
| P1 | 跨天衔接（酒店/交通）是否清楚 | 低 |
| P1 | 选中/编辑某个节点时不迷路 | 中 |
| P2 | 导出 PNG/PDF 好看 | 低 |

```
┌──────────┬─────────────┬─────────────┬─────────────┐
│ 总览      │  Day1       │  Day2       │  Day3       │  ← 列头（日期/天气）
├──────────┼─────────────┼─────────────┼─────────────┤
│ 樟宜区    │ [卡][卡]    │             │             │  ← 区域轨 + 单元格
│ 武吉士区  │             │ [卡][卡]    │ [卡]        │
│ 万礼区    │             │             │ [卡][卡]    │
└──────────┴─────────────┴─────────────┴─────────────┘
         ↑ SVG 连线层叠在单元格之上
```

| 模块 | 文件 | 职责 |
|------|------|------|
| 主视图 | `OverviewGraphView.tsx` | 网格壳层、三向滚动同步、列虚拟化 |
| 布局 | `layoutOverview.ts` | 区域×日期分组；列内 2 列 flex 换行；锚点计算 |
| 节点卡 | `OverviewNodeCard.tsx` | 与单日节点信息同级（类别/时间/tags/tips） |
| 连线 | `OverviewEdgeLayer.tsx` | 贝塞尔 SVG；跨日弧线路径 |
| 样式 | `OverviewGraphView.css` 等 | 网格线、区域轨、列头 |

**与单日模式的差距**

| 维度 | 单日 `ItineraryGraph` | 总览 `OverviewGraphView` |
|------|----------------------|--------------------------|
| 布局引擎 | dagre + React Flow | 手写 2 列网格 |
| 场景分组 | `SceneGroupNode` 背景框 | 无 |
| 连线 | `TripEdge` 专用组件、主路线动画 | 通用贝塞尔、易穿卡片 |
| 背景 | 径向渐变 + Flow 画布 | 扁平网格 + 半透明单元格 |
| 交互 | 拖拽、连线把手 | 仅点击选中 |

## 3. 混乱感根因诊断

### 3.1 布局：设计意图与实现不一致

设计文档（§3.3.1）写的是：**列内按 primary 边拓扑序，dagre LR 横向排列**。  
实际 `layoutOverview.ts` 将节点拓扑排序后，按 `idx % 2` 填入**两列换行网格**：

```typescript
// computeOverviewAnchors — 列内固定 2 列网格
const col = idx % perRow;  // perRow = 2
const row = Math.floor(idx / perRow);
```

**后果**

- 拓扑第 3 个节点会折到第二行左侧，但连线仍按 1→2→3 顺序画，**折线横穿其他卡片**。
- 同一区域内 3+ 个节点时，视觉顺序与阅读顺序（左→右）断裂。
- 行高按「全局该区域最大节点数」计算，稀疏天列留下大块空白，**节奏不均匀**。

### 3.2 连线层：几何与内容争抢

`OverviewEdgeLayer` 在节点中心之间画曲线，标签放在路径中点：

- 2 列布局下，横向/斜向线**必然穿过同行或邻行卡片**。
- 9px 交通 emoji + 时长文字与卡片标题、tags 叠在一起。
- 跨日边 `crossDay` 用抬升贝塞尔，多天多区域时**弧线交织成网**。
- 所有边同层级绘制，**无主路线视觉优先级**（单日模式 primary 边有 `animated`）。

### 3.3 节点卡：信息过载

`OverviewNodeCard` 在 132×76px（紧凑 108×64px）内展示：

- 类别图标 + 英文大写 label + 楼层
- 名称（最多 2 行）
- 时间段
- 最多 2 个 tag
- tips 黄字单行

在总览场景下，用户更需要 **「这是第几个点、叫什么、几点」**；tags/tips 属于详情层，挤在小卡里制造**彩色斑点 + 黄字噪音**。  
`design-taste-frontend` 原则：**旅行规划 = 时间、地点、路线清晰；特效不得遮挡内容**——当前违反「内容优先」。

### 3.4 网格视觉：边框与底色过重

```css
/* OverviewGraphView.css */
.overview-cell {
  border-right: 1px dashed var(--border);
  border-bottom: 1px solid ...;
  background: color-mix(..., 35%, transparent);
}
```

- 每个单元格独立底色 + 虚线竖线 → **棋盘格感**。
- 区域轨标签全用 `--accent` 琥珀色，与选中态 accent 描边**抢同一视觉锚点**（skill：全页 accent 应 <5%）。
- 角标「总览」与右上角 `overview-graph__mode-hint` **重复**。

### 3.5 导航：总览时失去「天」的锚点

`PreviewPane` 在 `graphViewMode === 'overview'` 时**隐藏 DayTabs**。  
用户只能横向滚动找天，没有：

- 列头点击聚焦
- 迷你时间轴 / 缩略导航
- 当前天高亮

长行程（>5 天触发紧凑 + 列虚拟化）进一步加剧**「我在看哪一天」**的迷失感。

### 3.6 区域语义薄弱

- `region` 来自节点或 `DayPlan.region`，LLM 输出不一致时行数膨胀。
- 区域轨仅文字右对齐，**无与单元格行的视觉绑定**（行背景、左侧色条等）。
- 同一区域跨多天重复出现行，但用户更关心「这天换区了吗」——缺少**日间区域迁移**提示。

### 3.7 锚点与 DOM 可能漂移

锚点按固定 `nodeWidth/nodeHeight` 计算，卡片因名称换行、tags 撑高时，**连线端点与真实卡片中心错位**，加重「线乱」观感。

## 4. 设计原则（提炼自 skill）

| 原则 | 总览模式落地 |
|------|-------------|
| 一个主锚点 | 用 **日期列** 或 **主路线序号** 作锚点；区域轨降饱和，不用 accent 铺满 |
| 节奏胜于装饰 | 8px 网格；行高随内容但设上限；减少单元格边框层数 |
| 信息优先 | 总览卡片只保留 3 字段；详情放侧栏 / hover |
| 类别色一致 | 类别色用于 **小圆点/左边线**，非整卡粗边框 |
| 选中用 accent 描边 | 与类别色脱钩，避免满屏彩色边框 |
| motion 克制 | 仅列聚焦、选中、切换 Tab 时 200ms 过渡 |

## 5. 方案头脑风暴

### 方案 A：矩阵进化版（推荐优先落地）

**思路**：保留「区域行 × 日期列」信息架构（与产品文档、用户心智一致），**修正布局与视觉层级**，改动可控。

```
┌────────┬── Day1 ──────────────┬── Day2 ──────────────┐
│        │  ①──②──③──④  →      │  ①──②  →             │  ← 列内单行 LR 链
│ 樟宜区 │  (仅序号+名+时间)     │                      │
├────────┼──────────────────────┼──────────────────────┤
│ 武吉士 │                      │  ①──②──③  →          │
└────────┴──────────────────────┴──────────────────────┘
```

| 改动点 | 说明 |
|--------|------|
| 列内布局 | 改为**单行横向链**（dagre LR 或简化为 flex + 固定间距）；节点 >4 时启用列内横向微滚动 |
| 节点形态 | **胶囊/芯片**：`序号 · 名称` + 次要行 `09:00–10:30`；类别用 6px 色点 |
| 连线 | **正交路由**（沿单元格中线水平走线，在列边界下降）；主路线 2px 实线，备选 1px 虚线 |
| 网格 | 去掉单元格虚线边框；**区域行交替底色**（`bg-elevated` / `bg-base`）；列间 1px 分隔 |
| 列头 | 点击列头 → 横向滚动居中 + 列背景 `accent-soft` 高亮 2s |
| 跨日 | 收拢为列顶/列底的 **「跨日连接点」**（小圆点 + 虚线竖井），避免弧线横穿矩阵 |
| 导航 | 总览时显示 **压缩版 Day Chips**（仅 `D1 D2 D3`），点击滚到列 |

**优点**：与现有数据结构、导出、虚拟化兼容。  
**缺点**：单日节点极多（>6/区）时仍需横向微滚或折叠。

---

### 方案 B：时间纵轴日历（Gantt 风）

**思路**：横轴 = 天，纵轴 = 当日时间；节点 `top` 由 `start_time` 决定。

```
        Day1          Day2
08:00   [酒店]        
10:00        [景点A]──[景点B]
14:00                   [午餐]
```

| 优点 | 直观对比「每天几点在干嘛」；连线自然竖横走向 |
| 缺点 | 无时间节点难排；跨区不在同一列；需较大纵向空间；与「区域行」语义冲突，需二选一或双轴 |

**适合**：用户常问「行程会不会太赶」时作为 **总览子视图**（Tab：区域矩阵 | 时间轴）。

---

### 方案 C：纵向「故事条」（按天滚动）

**思路**：每天一条横向卡片带，区域内嵌 mini 泳道；**纵向滚动浏览天**。

```
╔══ Day 1 · 10/16 晴 ═════════════════════════╗
║  樟宜区   ①机场 ──→ ②星耀 ──→ ③酒店         ║
╚════════════════════════════════════════════╝
╔══ Day 2 · 10/17 ═══════════════════════════╗
║  市区     ①鱼尾狮 ──→ ②午餐 ──→ ③滨海湾      ║
╚════════════════════════════════════════════╝
```

| 优点 | 移动端友好；每天独立、不会横向迷失；可复用单日 dagre 布局 |
| 缺点 | **无法一眼对比**「Day1 和 Day3 是否同一区域」；长行程纵向很长 |

**适合**：作为移动端总览默认，桌面保留方案 A。

---

### 方案 D：地铁图 / 示意图（强抽象）

**思路**：区域 = 水平「线路」；天 = 线上节点序列；刻意不保留地理比例。

| 优点 | 连线清晰、编辑感强（参考 Transit Map） |
| 缺点 | 与地图 Tab 语义重复；用户可能误以为地理相邻；实现需新布局引擎 |

**适合**：品牌差异化大改版时考虑，不建议作为近期首选。

---

### 方案 E：分层缩放（Bird's-eye → Detail）

**思路**：默认 **L0 鸟瞰**：每格只显示 `3 个点 + +2`；缩放或双击进入 **L1** 看全节点。

| 优点 | 7–14 天行程首屏不爆 |
| 缺点 | 多一层交互；与「一眼总览」略有张力 |

**适合**：与方案 A 组合——**紧凑模式默认 L0**，点击区域行展开 L1。

---

### 方案 F：地图缩略镶嵌

**思路**：每个日期列底部 80px 高度嵌入静态地图快照，节点为编号 Pin。

| 优点 | 强化「去哪」的地理直觉 |
| 缺点 | 渲染成本、瓦片版权、与右侧地图 Tab 重复 |

**适合**：Phase 4 或「导出海报」模式，不作默认总览。

## 6. 方案对比矩阵

|  | 一眼全天 | 区域感 | 顺序/路线 | 实现成本 | 与现架构兼容 |
|--|---------|--------|----------|----------|-------------|
| **A 矩阵进化** | ★★★★ | ★★★★★ | ★★★★ | 中 | ★★★★★ |
| B 时间纵轴 | ★★★ | ★★ | ★★★★★ | 高 | ★★ |
| C 故事条 | ★★★ | ★★★ | ★★★★ | 中 | ★★★ |
| D 地铁图 | ★★★★ | ★★★ | ★★★★★ | 很高 | ★ |
| E 分层缩放 | ★★★★★ | ★★★ | ★★★ | 中 | ★★★★ |
| F 地图镶嵌 | ★★★ | ★★★★ | ★★★ | 高 | ★★ |

**结论**：短期 **方案 A** 投入产出比最高；中期可加 **方案 E** 的 L0 折叠；长期移动端用 **方案 C** 作为响应式变体。

## 7. 推荐落地路线（分阶段）

### Phase 1 · 止血（1–2 天）— 不改信息架构

目标：不明显改布局结构，但**立刻减轻混乱**。

1. **精简总览卡片**  
   - 仅保留：序号（新增）、类别色点、名称、时间  
   - 隐藏 tags / tips / floor（侧栏已有详情）  
   - 边框改为 `1px solid var(--border)`，选中时 `accent` 外描边  

2. **弱化网格**  
   - 移除 `overview-cell` 虚线右边框与半透明底  
   - 区域行 `nth-child(even)` 轻底色  
   - 区域轨文字改 `text-muted`，去掉 accent  

3. **连线降噪**  
   - 非选中边 `opacity: 0.35`  
   - 标签默认隐藏，**选中边或 hover 边** 才显示时长  
   - 主路线 `stroke-width: 2.5`，备选 `1.5` 虚线  

4. **去掉重复「总览」角标**（保留一处即可）

**验收**：同一行程截图对比，卡片面积视觉噪音减少约 40%；连线不再遮挡标题为主。

---

### Phase 2 · 布局正本（3–5 天）

目标：列内路线**可读**。

1. **`layoutOverview` 列内改为单行 LR**  
   - `perRow = nodes.length`（或 `min(nodes.length, 5)` 超出则 `overflow-x: auto`）  
   - 锚点 X 按链式累加：`prevX + nodeWidth + gap`  
   - 对齐 `sortNodesByPrimaryEdges` 顺序  

2. **正交连线**（替换纯贝塞尔）  
   - 同单元格：水平线连接卡片垂直中心  
   - 跨单元格同天：沿区域行间隙走线（可选 Phase 3）  

3. **列头交互**  
   - 点击列头 → `scrollIntoView` + 临时高亮  
   - 总览时工具栏显示 `DayChips`（复用 `DayTabs` 样式压缩版）  

4. **跨日边专用通道**  
   - 矩阵最顶部 24px「跨日带」，跨日弧线只走该带  

**验收**：3 节点以上区域，连线不再穿过卡片；用户 3 秒内能说出 Day2 第二个点。

---

### Phase 3 · 体验抛光（可选）

- 区域行左侧 **4px 类别/区域色条**（区域色可从首日该 region 首节点类别推导）  
- 紧凑模式（>5 天）默认 **方案 E**：每格最多展示 3 节点 + `+N`  
- 列虚拟化时边也按可见列裁剪绘制  
- 导出专用主题：浅底高对比（PDF 友好）  
- `ResizeObserver` 实测卡片高度，修正锚点

## 8. 总览节点视觉规范（建议稿）

与单日 `TripNode` 差异化：**总览 = 索引，单日 = 详情**。

```
┌─────────────────────────┐
│ ● ③  滨海湾花园          │  ← 6px 类别色点 + 序号 + 名称 12px/600
│      14:00–16:00        │  ← 时间 10px muted, tabular-nums
└─────────────────────────┘
        胶囊 min 96×44，紧凑 80×36
```

| Token | 值 |
|-------|-----|
| 序号 | `font-variant-numeric: tabular-nums`；颜色 `text-dim` |
| 名称 | 单行 `ellipsis`；紧凑模式不缩字号，只缩宽度 |
| 选中 | `box-shadow: 0 0 0 2px var(--accent-soft)`；无渐变底 |
| 可选节点 | `border-style: dashed`；opacity 0.75 |

## 9. 连线视觉规范（建议稿）

| 类型 |  stroke | 标签 |
|------|--------|------|
| primary | `#94a3b8` 55% → 选中 `accent` | hover/选中显示 `🚇 12m` |
| alternative | 虚线 4 4，opacity 0.3 | 同上 |
| cross_day | 顶部通道 `#f59e0b` 45%，虚线 | 显示「次日」或交通方式 |

路径策略：

```
同格：  [A]──────[B]──────[C]     水平中线
跨格：  [A]──┐
            └──（行间隙）──┐
                          [B]
```

## 10. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 列宽固定导致节点挤出 | 列内 `overflow-x: auto` + 渐隐遮罩提示可横滚 |
| 虚拟化列与跨日边 | 跨日边走顶部通道，不依赖不可见列的节点位置 |
| LLM `region` 不一致 | 后端 prompt 约束 + 前端合并相似区域（同义词表） |
| 导出与屏显样式分叉 | `data-export-overview` 时注入一套 `@media print` 变量 |

---

## 11. 总结

当前总览「混乱」**不是单一 CSS 问题**，而是三层叠加：

1. **结构层**：2 列换行与路线拓扑不匹配 → 连线穿卡  
2. **信息层**：总览卡片承载与单日相同的详情密度 → 视觉噪音  
3. **导航层**：隐藏 DayTabs 后缺少「天」的锚点 → 横向滚动迷失  

**推荐路径**：先做 Phase 1 降噪（低成本立竿见影），再做 Phase 2 列内单行 LR + 正交连线（对齐设计文档原意）。方案 B/C 可作为后续「总览子视图」扩展，不必替换主矩阵。
