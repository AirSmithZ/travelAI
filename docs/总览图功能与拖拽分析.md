## 1. 当前总览图全部功能（详细说明）

### 1.1 产品定位

总览图是行程预览区的**矩阵式信息图**：横轴为「天」，纵轴为「区域」，单元格内展示当天在该区域的景点/活动节点及路线顺序。用户可在一屏内扫读多日、多区行程，并进行选中、跳转地图、纵向换区等轻量编辑。

入口：`PreviewPane` 在 `graphViewMode === 'overview'` 时渲染 `OverviewGraphView`。

### 1.2 布局结构

```
┌────────┬── Day1 · 日期 · 星期 · 温度 ──┬── Day2 · ... ──┐
│ 区域轨 │  单元格（樟宜区 × Day1）        │  单元格         │
│ 樟宜区 ├──────────────────────────────┼─────────────────┤
│ 武吉士 │  单元格（武吉士 × Day1）        │  单元格         │
│ 万礼区 ├──────────────────────────────┼─────────────────┤
│  ...   │  ...                           │  ...            │
└────────┴────────────────────────────────┴─────────────────┘
         ↑ 矩阵主体（overview-matrix）可横纵滚动
```

| 区域 | 组件 / 类名 | 职责 |
|------|-------------|------|
| 左上角占位 | `overview-shell__corner` | 与列头、区域轨对齐的固定角 |
| 列头 | `overview-shell__header` | 每天一列，展示 Day 序号、月日、星期、天气 |
| 左侧区域轨 | `overview-shell__rail` | 竖排区域名，行高与矩阵同步 |
| 矩阵主体 | `overview-shell__body` → `overview-matrix` | 天×区域单元格 + 跨区 SVG 边层 |
| 底栏图例 | `itinerary-graph__legend` | 主路线 / 备选项 / 跨区 线型说明 + 操作提示 |

### 1.3 列头（Day Column Header）

- **数据来源**：`day.day_index`、`day.date`、`day.weekday`、`day.weather`、`day.label`
- **展示格式**：
  - 主行：`Day N · M月D日 · 星期 · ☀ 26~34°C`
  - 副行（有数据时）：`day.label · weather.description`（超长省略，hover `title` 全文）
- **列头高度**：`COLUMN_HEADER_HEIGHT = 52px`（双行时垂直居中）
- **交互**：点击列头 → `scrollToDay(i)`，横向平滑滚动到该天，并 `setActiveDay(i)`，列头短暂高亮（`focusedDayIndex`，2 秒后消失）
- **外部联动**：`overviewScrollDay` 非空时自动滚动到对应天并清空（供 DayChips 等入口调用）

### 1.4 左侧区域轨（Region Rail）

- **区域列表**：`collectRegionsInOrder(days)` — **先按天序收集 `day.region`**，再补充节点中出现的其他区域；空区也占位，顺序不随节点拖拽变化
- **区域解析**：`getNodeRegion(node, day)` → `node.region` → `day.region` → `'其他'`
- **行高**：`regionHeights` — 取该行所有天列单元格内容高度的最大值；**默认空行** `EMPTY_CELL_HEIGHT = 96px`（原 48px 的两倍）
- **行底色**：`getRegionTintVar(regionIndex)` 循环使用 `--region-tint-a/b/c`，100% 饱和度
- **拖拽反馈**：拖拽激活时冻结 `layoutSnapshot`，落点解析与左侧轨行高一致，不因区域内是否有节点而改变顺序

### 1.5 单元格（Overview Cell）

每个单元格对应 `(dayIndex, region)` 唯一键 `cellKey(dayIndex, region)`。

| 能力 | 说明 |
|------|------|
| 节点分组 | 仅渲染 `getNodeRegion(n) === region` 的节点 |
| 路线排序 | `sortNodesByPrimaryEdges` 按 primary 边拓扑序 |
| 水平路线链 | `OverviewRouteChain`：节点卡 + Bezier 通勤边 + 场景组虚线框 |
| 节点间距 | 卡片间 `nodeGap` 12px（紧凑 8px），连线区 `commuteWidth` 100px，保证线条完整露出 |
| 连线样式 | `OverviewBezierEdge` 加粗描边 + accent 微光，z-index 高于场景组、低于节点 |
| 单元格底色 | 区域 tint 10% 混入 `--bg-base` |
| 聚焦列 | `activeDayIndex` 或 `focusedDayIndex` 匹配时 `overview-cell--focused` |
| 落点高亮 | 拖拽时仅**当天列**的目标区域单元格 `overview-cell--drop-target` |
| 长备注 | `getCellLongNote` 检测 tips 总长 > 40 时底部 `OverviewCellNote` |
| 空单元格 | 无节点时不渲染路线链，仍占位保持矩阵整齐 |

### 1.6 单元格内路线链（OverviewRouteChain）

复用单程图视觉语言（`TripNode` / `TripEdge` 尺寸常量），**排序与连线与 `ItineraryGraph` 同源**：

| 元素 | 组件 | 说明 |
|------|------|------|
| 节点顺序 | `getOrderedRegionNodes` | 全天 `sortNodesByPrimaryEdges` 后过滤到本格，保持主链顺序 |
| 单元格内连线 | `collectIntraCellEdgePlacements` | 直接遍历 `day.edges` 中 primary 边，两端均在格内且左→右 |
| 跨区连线 | `OverviewEdgeLayer` | z-index 8，永久渲染所有天的跨区边 |
| 矩阵列渲染 | `matrixDayIndices` | **所有天列永久渲染**路线链（列头仍可按需虚拟化） |

### 1.7 跨区连线层（OverviewEdgeLayer）

- **数据**：`getCrossRegionEdges(day)` — 同天、两端节点 `region` 不同的 primary/alternative 边
- **锚点**：`computeOverviewAnchors` 计算各节点在矩阵内的中心坐标
- **绘制**：SVG 折线（竖-横-竖），可点击选中；线型区分主路线 / 备选项 / 跨区
- **已移除**：跨日连线渲染（产品决策：总览不画跨天边）

### 1.8 动态尺寸与性能

| 机制 | 触发条件 | 行为 |
|------|----------|------|
| 动态列宽 | 每天单元格 `contentWidth` 取 max | `columnWidths[dayIndex]` 随内容撑开 |
| 动态行高 | 每区域行取所有天列 max | `regionHeights` |
| 紧凑模式 | `days.length > 5` | 更小节点、更窄列宽、`overview-graph--compact` |
| 列虚拟化 | 紧凑模式且非导出 | `useOverviewColumnVirtualizer` 只渲染可见天列 |
| 导出捕获 | `exportOverviewCapture` | 关闭虚拟化，渲染全部列供截图 |

详见 [总览图导出功能分析.md](./总览图导出功能分析.md)。

### 1.9 滚动同步

`useOverviewScrollSync` 三向联动：

- 主体横向滚动 ↔ 列头横向滚动
- 主体纵向滚动 ↔ 区域轨纵向滚动
- 使用 `syncing` 锁 + `requestAnimationFrame` 防止循环触发

### 1.10 选择与清空

- 点击矩阵空白（`body` 自身）→ `selectNode(null)` + `selectEdge(null)`
- 底栏图例：主路线实线、备选项虚线、跨区特殊线型

### 1.11 已移除功能

| 功能 | 状态 |
|------|------|
| 左上角 `OverviewLegend` 类别图例 | 已移除 |
| 鸟瞰模式（缩略全图） | 已移除 |
| 跨日连线 | 不渲染 |
| 节点横向拖拽换天 | **禁止**（见 §2） |

### 1.12 数据字段契约

| 字段 | 用途 | 前后端 |
|------|------|--------|
| `node.region` | 决定节点落在哪一行 | 后端 `normalize_node_regions` 补全；前端 `ensureDayNodeRegions` |
| `node.overview_offset` | 单元格内水平微调（`x` 有效，`y` 恒为 0） | 换区时清除，避免飘逸 |
| `day.edges` | 路线顺序、跨区边、备选边 | 只读展示，拖拽不改边 |
| `day.weather` | 列头温度与图标 | 只读展示 |

## 2. 拖拽交互契约：仅纵向换区，禁止跨天列

### 2.1 产品规则

| 规则 | 说明 |
|------|------|
| **允许** | 在同一「天」列内，纵向拖动节点到不同「区域」行 |
| **禁止** | 横向拖动到其他「天」列（左右表格不能改变区域归属的天） |
| **禁止** | 拖出当天列宽度范围后的落点提交 |
| **预览** | 仅 `translateY(dy)`，不产生横向位移 |
| **提交** | 仅当 `targetRegion !== session.region` 且指针在当天列内时写入 |
| **写入字段** | 只更新当前节点的 `{ region, overview_offset: undefined }` |

### 2.2 实现要点（`useOverviewNodeDrag`）

**激活阈值**（`OVERVIEW_DRAG_ACTIVATION_PX = 8`）：

- `pointerdown` 不立即 `preventDefault`，不显示 preview
- 纵向位移 ≥ 8px 且 `|dy| ≥ |dx|` 才激活拖拽（避免与横向滚动、单击选中冲突）
- 激活时冻结 `layoutSnapshot`（regions + regionHeights + 列宽），拖拽全程左侧轨顺序与行高不变
- 激活后才 `setPointerCapture` 并显示 `dragPreview`

```
pointerdown（节点）
  → 记录 session: { nodeId, dayIndex, region, pointerId, startX, startY, activated: false }
  → 不设置 preview

window pointermove
  → 若未激活：|dy|≥8 且纵向意图 → activateDrag
  → dy = clientY - startY
  → matrixPoint → 判断 isInDayColumn(pt.x, session.dayIndex)
     ├─ 否：preview dy=0，targetRegion 保持原区域（不跟随、不覆盖其他列）
     └─ 是：preview dy=dy，targetRegion = resolveRegionAtMatrixY(pt.y)

window pointerup / 节点 pointerup
  → 若未激活：放弃（单击选中正常触发）
  → 若不在当天列内：放弃提交
  → 若 targetRegion !== region：onCommit(dayIndex, nodeId, { region, fromRegion })
  → endDrag()
```

**关键函数**：

- `resolveRegionAtMatrixY(matrixY, layout)` — 根据矩阵 Y 坐标命中区域行
- `isInDayColumn(matrixX, dayIndex, layout)` — `columnOffsets[dayIndex]` ~ `+ columnWidths[dayIndex]`

### 2.3 视图层配合

| 文件 | 改动 |
|------|------|
| `OverviewGraphView` | `handleDragCommit` → `recordItineraryHistory()` + `updateNode({ region, overview_offset: undefined })` |
| `OverviewGraphView` | 换区后 `regionEnter` 状态驱动入场动画（280ms，方向感知） |
| `OverviewRouteChain` | `transform: translateY(${dy}px)`；`--region-enter` 动画类 |
| `OverviewGraphView` | 单元格 `isDropTarget` 需同时匹配 `targetRegion` 与 `dayIndex` |
| 底栏提示 | 「纵向拖拽换区（限当天列）· 单击选中 · 双击打开地图 · ⌘Z 撤销」 |

### 2.4 撤销栈（换区专用）

- **存储**：`usePlanStore.itineraryHistories[planId]`，`past` / `future` 各最多 50 步（`structuredClone`，不持久化）
- **入栈时机**：换区提交前 `recordItineraryHistory()` 快照当前 itinerary
- **快捷键**：总览视图内 `⌘Z` / `Ctrl+Z` 撤销，`⌘⇧Z` / `Ctrl+Shift+Z` 重做（输入框内不拦截）
- **工具**：`utils/itineraryHistory.ts`

### 2.5 布局层约束

`layoutOverview` / `computeCellLayout` 中 `nodeOffset` 已将 `overview_offset.y` 强制为 0：

```ts
function nodeOffset(node) {
  const raw = node.overview_offset ?? { x: 0, y: 0 };
  return { x: raw.x, y: 0 };
}
```

区域归属仅由 `node.region` 决定节点进入哪个单元格，**不存在**通过改 `dayIndex` 移动节点的路径。

## 3. 拖拽问题根因与修复记录

### 3.1 问题清单

| 现象 | 根因 | 修复 |
|------|------|------|
| 横向拖到其他天列会换区/覆盖 | 落点仅用 Y 解析区域，未校验 X 是否在当天列 | `isInDayColumn` 门控预览与提交 |
| 拖拽时节点横向飘逸 | preview 使用 `translate(dx, dy)` + `overview_offset.x` 参与 | 预览仅 `translateY(dy)`；换区清除 `overview_offset` |
| 拖拽卡住 / pointer 丢失 | `pointermove/up` 绑在单元格内节点，跨格后事件丢失 | 改为 `window` 级 `pointermove/up/cancel` |
| 拖完后整表乱跳 | 换区后保留旧 `overview_offset` 导致布局重算异常 | 提交时 `overview_offset: undefined` |
| 落点高亮整行所有天列 | `isDropTarget` 只比较 `targetRegion` | 单元格额外比较 `dragPreview.dayIndex === dayIndex` |
| 误用全量同步 | 若调用 `syncItineraryMeta` 会重写整份 itinerary | 拖拽仅走 `updateNode` 单节点 patch |

### 3.2 提交数据范围（「不要更新所有数据」）

`usePlanStore.updateNode` 实现为**不可变单节点 patch**：

```ts
days.map((day, i) => {
  if (i !== dayIndex) return day;
  return {
    ...day,
    nodes: day.nodes.map((n) =>
      n.id === nodeId ? { ...n, ...partial } : n
    ),
  };
});
```

- 仅匹配 `dayIndex` 的那一天、匹配 `nodeId` 的那一个节点被更新
- **不**调用 `syncItineraryMeta`、**不**重写 edges、**不**批量改其他节点 region
- 换区后布局由 `layoutOverview` 根据新 `region` 自动把节点渲染到新行，无需手动搬移数组

## 4. 总逻辑追溯（数据流与文件索引）

### 4.1 渲染主链路

```
PreviewPane (graphViewMode === 'overview')
  └─ OverviewGraphView
       ├─ usePlanStore.getItinerary()
       ├─ layoutOverview(days, metrics)          ← utils/layoutOverview.ts
       │    ├─ collectRegionsInOrder
       │    ├─ computeCellLayout (per cell)
       │    └─ columnWidths / regionHeights / columnOffsets
       ├─ computeOverviewAnchors                   ← 跨区边锚点
       ├─ getCrossRegionEdges (per day)            ← utils/overviewRoute.ts
       ├─ useOverviewScrollSync                  ← hooks/useOverviewScrollSync.ts
       ├─ useOverviewColumnVirtualizer           ← hooks/useOverviewColumnVirtualizer.ts
       ├─ useOverviewNodeDrag                    ← hooks/useOverviewNodeDrag.ts
       │
       ├─ 列头 buttons → scrollToDay
       ├─ 区域轨 labels
       ├─ 矩阵 cells
       │    └─ OverviewRouteChain
       │         ├─ buildCellRouteSegments / groupRouteSegments
       │         ├─ OverviewNodeCard
       │         └─ OverviewBezierEdge
       └─ OverviewEdgeLayer (SVG 跨区边)
```

### 4.2 拖拽提交链路

```
OverviewRouteChain.onPointerDown
  → makeDragDown(dayIndex, region)
  → useOverviewNodeDrag.onNodePointerDown
  → [window pointermove 更新 dragPreview]
  → finishDrag → onCommit
  → OverviewGraphView.handleDragCommit
  → usePlanStore.updateNode(dayIndex, nodeId, { region, overview_offset: undefined })
  → React 重渲染 → layoutOverview 重算 → 节点出现在新区域行
```

### 4.3 区域字段全链路

| 布局 | `layoutOverview` | 按 `region` 过滤节点到单元格 |

## 5. 与 Skill 指引的对应关系

本次分析参照项目内 skill 的**分层与最小副作用**原则（非聊天 UI 本身，但工程约定一致）：

| 原则 | 在总览图中的体现 |
|------|------------------|
| 状态单一来源 | 行程数据只在 `usePlanStore`；拖拽 preview 是本地 UI 状态 |
| 确认再写入 | 拖拽在 `pointerup` 且区域变化时才 `onCommit`，非 move 过程中写 store |
| 最小 patch | `updateNode` 单节点，避免 `syncItineraryMeta` 全量重写 |
| 视图与数据分离 | `layoutOverview` 纯函数根据 itinerary 算布局；`dragPreview` 仅影响 transform |
